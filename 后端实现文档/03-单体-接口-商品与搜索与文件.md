# 03 · 单体接口：商品 / 分类 / 搜索 / 文件

> 代码位置：`ershou-server`（Spring Boot 3.3.5 + MyBatis-Plus 3.5.9 + Sa-Token 1.39.0 + JDK 21）。
> 覆盖 `module/item`、`module/search`、`module/file`，共 **12 个接口**：items 8 个、categories 1 个、search 2 个、files 1 个。
> 所有接口前缀 `/api/v1`，端口 `8080`。文档基于 2026-10-30 的源码快照，未在源码中出现的字段/行为一律不写；不确定处标注「以源码为准」。

## 一、模块概览

| 项 | 内容 |
| --- | --- |
| 基础路径 | `/api/v1`（items / categories / search / files） |
| 统一返回 | `Result<T> = {code, message, data, traceId}`，成功 `code=0`、`message="ok"`；业务错误 HTTP 仍为 200，靠 `code` 判断 |
| 分页返回 | `PageResult<T> = {total, pageNum, pageSize, records}`（字段名就是 `records`，不是 `list`） |
| 鉴权方式 | 请求头 `Authorization: Bearer <token>`（Sa-Token，`token-name=Authorization`、`token-prefix=Bearer`） |
| 公开接口 | `GET /api/v1/items`、`GET /api/v1/items/{id}`、`GET /api/v1/categories`、`GET /api/v1/search/status`（`SaTokenConfig` 白名单） |
| 需登录 | 发布 / 编辑 / 下架 / 重新上架 / 二次申请上架 / 我的发布 / 上传文件 |
| 需运营权限 | `POST /api/v1/search/reindex`（Controller 内 `AdminAuthService.requireAdminId()` 校验，不是 Sa-Token 注解角色） |
| 涉及表 | `item`、`item_category`；间接：`sys_user`（卖家信息）、`favorite`（收藏态）、`order`/面交意向（下架时联动关闭）、`item_review`（上架审核队列） |
| 搜索 | Elasticsearch 8，索引默认 `ershou_item`，配置前缀 `ershou.search.*` |
| 文件存储 | MinIO（`ershou.storage.mode=minio`，默认）或本地磁盘（`mode=local`），配置前缀 `ershou.storage.*` |
| 关键配置 | 商品有效期 `ershou.item.valid-days`（默认 7 天）、限时开关 `ershou.item.validity-enabled`（默认 true）；详情缓存 `ershou.cache.*` |

> 补充：Jackson 全局配置 `default-property-inclusion: non_null`，**值为 null 的字段不会出现在响应 JSON 中**（例如 `expireAt=null`、`lastError=null`、`shopName=null`）；日期格式 `yyyy-MM-dd HH:mm:ss`、时区 `Asia/Shanghai`。

### 鉴权实现细节（必须照着做）

`SaTokenConfig` 用 `SaInterceptor` 拦截 `/api/**`，白名单直接放行：`/api/v1/auth/**`、`/api/v1/categories`、`/api/v1/schools/**`、`/api/v1/map/**`、`/api/v1/trade-points/**`、`/api/v1/platform/shop/**`、`/api/v1/search/status`、`/api/v1/items`、`/api/v1/items/*`、`/api/v1/users/*/profile`。

注意两点：

1. `/api/v1/items/*` 会把 `/items/mine`、`/items/{id}` 这类单段路径一并「白名单」（`/items/{id}/offline` 等多段路径不匹配），因此**商品写接口全部在 Controller 方法内显式 `StpUtil.checkLogin()`**，不能依赖拦截器。
2. 未登录调用需登录接口时，抛 `NotLoginException`，由 `GlobalExceptionHandler` 转成 `code=10002`；无运营权限抛 `BizException(NO_PERMISSION)`，转成 `code=10003`。

> 「机审已移除」是当前实现的重要前提：发布**不再做关键词机审**，直接落库为 `status=2`（在售）；编辑也**不修改状态**。运营的「上架审核」是事后确认（写入 `item_review` 队列 / 推送），不拦截发布与编辑。

## 二、数据模型简表

| `stock` | INT | 库存，默认 1 |
| `is_unique` | TINYINT | 孤品标记，默认 1 |
| `cover_url` | VARCHAR(255) | 封面 = `images[0]` |
| `images` | JSON | 图片 URL 数组，1~9 张；实体里是 JSON 字符串，VO 里是 `List<String>` |
| `video_url` | VARCHAR(255) | 视频地址，可空 |
| `trade_mode` | TINYINT | 发布固定写 1（仅面交） |
| `prefer_point_id` | BIGINT | 常用面交点 id，可空 |
| `seller_type` | TINYINT | 1=个人卖家（发布固定写 1），2=平台自营（由 platform 模块直插） |

| `status` | TINYINT | 商品状态，见第四节状态码表 |

| `last_live_title` / `last_live_desc_hash` | VARCHAR(120) / CHAR(32) | 上架时（审核员已看过）的标题快照与描述 MD5，用于识别在售期间改名/改描述 |
| `expire_at` | DATETIME | 有效期截止；限时关闭时为 NULL（永久有效） |
| `published_at` | DATETIME | 发布时间；重新上架会刷新 |
| `view_count` / `chat_count` / `fav_count` | INT | 浏览 / 私聊 / 收藏计数 |
| `version` | INT | 乐观锁 |
| `created_at` / `updated_at` | DATETIME | 时间戳（增量同步 ES 依赖 `updated_at`） |

## 三、接口清单

### 3.1 商品（`ItemController`，8 个）

Controller 基路径 `/api/v1/items`。公开读接口用 `currentUserId()` 取「可选登录态」：未登录返回 null，按未收藏处理。

#### 1. 商品列表
- **方法与路径**：`GET /api/v1/items`
- **鉴权**：公开（登录后额外返回本人的 `favorited` 收藏态）
- **请求参数**：

| 位置 | 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| query | `pageNum` | long | 否 | 页码，默认 1 |
| query | `pageSize` | long | 否 | 每页条数，默认 20；超过 100 时按 100 截断 |
| query | `keyword` | string | 否 | 关键词；有值且 ES 可用时走 Elasticsearch，否则 MySQL `LIKE title OR description` |
| query | `categoryId` | long | 否 | 按分类精确筛选 |
| query | `campusId` | long | 否 | 按校区精确筛选 |
| query | `sellerId` | long | 否 | 按卖家精确筛选 |
| query | `preferPointId` | long | 否 | 按单个面交点精确筛选；**传了它就不会走 ES**（索引里没有该字段） |
| query | `preferPointIds` | string | 否 | 一次查一组点位，逗号分隔如 `11,12,13`；服务端去重、最多取 50 个（超出静默截断）；与 `preferPointId` 同时传时以集合为准 |
| query | `sort` | string | 否 | `latest`（默认）/ `price_asc` / `price_desc`；非法值按 `latest` 处理 |

- **请求体**：无
- **响应示例**：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "total": 37,
    "pageNum": 1,
    "pageSize": 20,
    "records": [
      {
        "id": 1024,
        "title": "九成新自行车",
        "price": 220.00,
        "originalPrice": 899.00,
        "negotiable": 1,
        "conditionLevel": 2,
        "conditionText": "几乎全新",
        "coverUrl": "http://127.0.0.1:9010/ershou/item/2026/10/xxxx.jpg",
        "images": ["http://127.0.0.1:9010/ershou/item/2026/10/xxxx.jpg"],
        "categoryId": 3,
        "categoryName": "交通工具",
        "campusId": 1,
        "preferPointId": 8,
        "preferPointName": "一号教学楼门口",
        "preferPointGuide": "从南门进入直走 200 米",
        "sellerType": 1,
        "status": 2,
        "statusText": "在售",
        "stock": 1,
        "isUnique": 1,
        "viewCount": 43,
        "favCount": 5,
        "favorited": true,
        "publishedAt": "2026-10-29 10:12:00",
        "expireAt": "2026-11-05 10:12:00",
        "seller": {
          "id": 21,
          "nickname": "小明",
          "avatar": "http://.../a.jpg",
          "creditScore": 96,
          "identityFlag": 1
        }
      }
    ]
  },
  "traceId": "trace-xxx"
}
```

- **业务规则 / 校验**：
  - 固定只查 `status=2`（在售）；`latest` 排序为 `published_at DESC, id DESC`，`price_asc/price_desc` 按价格排序；**MySQL 兜底路径下没有关键词时排序规则相同**。
  - ES 路径条件：`ershou.search.enabled=true` + `keyword` 非空 + `preferPointId` 为空 + ES 健康（未熔断、客户端存在）。ES 检索 DSL 固定过滤 `status=2`，并叠加 `categoryId/campusId/sellerId`；关键词用 `multi_match`（`title^3`、`categoryName^2`、`description`，`best_fields`、`operator=or`）；有词时 `latest` 按 `_score DESC, publishedAt DESC, id DESC`，无词时按 `publishedAt DESC, id DESC`。
  - ES 只返回「命中 id + total + 高亮」，随后**回 MySQL 批量取最新字段并按 ES 顺序组装**；回库后再次筛 `status==2`（索引短暂不一致时以库为准），因此 `total` 来自 ES、`records` 可能少于 total。
  - 高亮片段写入 `highlightTitle` / `highlightDescription`，标签固定 `<em>...</em>`，ES 侧 `encoder=html` 已转义。
  - 深分页保护：`from + pageSize > 10000`（ES `max_result_window`）时抛内部异常，**静默回落 MySQL**，不计入 ES 熔断。
  - ES 异常时：若 `ershou.search.fallback-to-db=true`（默认）则降级 MySQL LIKE；若为 `false` 则抛 `SYSTEM_ERROR`「搜索服务暂时不可用，请稍后再试」。开关开启、有关键词、但 `supports()` 为 false（如 ES 不健康）且 `fallback-to-db=false`，同样抛该错误。
  - 分类名与点位名走 `DictionaryCache`（Redis 字典缓存，批量 MGET），卖家信息一次批量查询；`viewCount` 会叠加 Redis 中尚未回写 DB 的浏览量增量。
  - 列表 VO **不填充 `description`**（`ItemService.assemble` 未赋值）；因 Jackson `default-property-inclusion=non_null`，响应里不会出现该字段。需要描述请调详情接口。
  - 源码现状提醒：`supports()` 只排除了 `preferPointId`，**没有排除 `preferPointIds`**；带 `keyword + preferPointIds` 且 ES 可用时会走 ES，而 ES 查询不包含点位过滤，该条件会被忽略。实现时若想修正，应在 `supports()` 中一并排除，或在 DSL 中补字段（以源码为准）。
- **可能错误码**：
  - `90001 SYSTEM_ERROR`：ES 不可用且 `ershou.search.fallback-to-db=false`（仅带关键词时）。
  - 其余情况正常返回（无结果也是 `code=0`、`total=0`）。

#### 2. 我的发布
- **方法与路径**：`GET /api/v1/items/mine`
- **鉴权**：需要登录（Controller 内 `StpUtil.checkLogin()`；虽然路径命中白名单，仍会显式校验）
- **请求参数**：

| 位置 | 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| query | `pageNum` | long | 否 | 默认 1 |
| query | `pageSize` | long | 否 | 默认 20；超过 100 按 100 截断 |

- **请求体**：无
- **响应示例**：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "total": 3,
    "pageNum": 1,
    "pageSize": 20,
    "records": [
      {"id": 1024, "title": "九成新自行车", "status": 2, "statusText": "在售", "favorited": false}
    ]
  },
  "traceId": "trace-xxx"
}
```

- **业务规则 / 校验**：
  - 按当前登录用户 `sellerId` 查询，**不按状态过滤**（草稿/审核中/在售/已售出/下架/过期/违规都会出现），按 `id DESC` 排序。
  - 分页大小上限 100；`favorited` 同样按本人收藏回填。
  - 组装字段与列表接口一致（列表 VO，不含 `description`）。
- **可能错误码**：
  - `10002 NOT_LOGIN`：未登录 / 登录失效。

    "categoryId": 3,
    "categoryName": "交通工具",
    "campusId": 1,
    "preferPointId": 8,

    "favCount": 5,
    "favorited": false,
    "publishedAt": "2026-10-29 10:12:00",
    "expireAt": "2026-11-05 10:12:00",
    "seller": {
      "id": 21,
      "nickname": "小明",
      "avatar": "http://.../a.jpg",
      "creditScore": 96,
      "identityFlag": 1
    }
  },
  "traceId": "trace-xxx"

```

- **业务规则 / 校验**：
  - 读缓存：`ershou:item:detail:{id}`，TTL `ershou.cache.item-detail-ttl`（默认 10 分钟，写入时加 0~10% 随机抖动防雪崩）。
  - 防穿透：`ershou:item:null:{id}` 空值哨兵（TTL 默认 60 秒）。请求先查哨兵，命中直接抛「商品不存在」；回源发现库里也没有时，先写哨兵再抛异常。
  - 防击穿：走 `JsonCache.getOrLoad` 的轻量重建锁（`ershou:item:detail:{id}:rebuild`，TTL 5 秒）；未抢到锁的请求按 `rebuild-wait-millis`（默认 50ms）轮询等待，总等待上限 `max-rebuild-wait-millis`（默认 500ms），超限或锁消失后才自行回源。
  - 命中缓存时 `vo` 是本次反序列化的副本，之后的浏览量叠加与收藏态填充**不回写缓存**；不要在详情里加 `cache.set` 回写，否则会把某个用户的 `favorited=true` 写进共享缓存。
  - 浏览量：每次详情请求执行 `INCR ershou:item:view:{id}`（首次自增设置 2 小时 TTL 并把商品 id 加入 `ershou:item:view:dirty` 集合），把当前未回写增量加到 `viewCount` 上返回；由定时任务每 10 分钟批量回写 `item.view_count`。Redis 异常时该次不计数、展示已回写值。
  - 返回包含 `description`（loader 中显式赋值）；分类名、点位名走字典缓存（单条 GET），卖家信息单查。
  - 不校验状态：即使商品已下架/售出，详情仍可读取（是否对外展示由前端按 `status` 处理）。
- **可能错误码**：
  - `30001 ITEM_NOT_FOUND`：商品不存在（含空值缓存命中）。

```

- **业务规则 / 校验**：
  - **新号发布限额**：若卖家 `sys_user.created_at` 在 7 天内，按「每天」限流。Redis key `ershou:limit:post:{userId}:{yyyyMMdd}`，首次 `INCR` 返回 1 时设 1 天 TTL；上限 `limit = user.publishLimit`，为空则取 5。计数先加后判，超过 `limit` 抛 `PUBLISH_LIMIT`，消息为「新账号每日最多发布 N 件，明天再来吧」。
  - **机审已移除**：不调用任何关键词审核，`status` 直接为 `2`（在售）。
  - 落库字段：`sellerId=当前登录用户`；`schoolId/campusId` 取自卖家资料；`coverUrl=images[0]`；`images` 序列化为 JSON 字符串；`tradeMode=1`；`sellerType=1`；`negotiable/stock/isUnique` 的 null 兜底；`expireAt = now + validDays`（`ershou.item.valid-days`，默认 7），若 `ershou.item.validity-enabled=false` 则写 NULL（永久有效）；`publishedAt=now`；`viewCount/chatCount/favCount=0`；`version=0`；同时写入 `lastLiveTitle` 与 `lastLiveDescHash`（描述 MD5）。
  - 事务提交后：同步单条 ES 索引（`ItemIndexService.syncById`）+ 清商品详情/空值缓存并 bump 地图版本（`CacheEvictor.itemChanged`）。
  - 因发布即 `status=2`，还会调用 `itemReviewService.onItemLiveOptimistic(itemId, TYPE_NEW)` 登记到运营「上架审核」队列（只做事后确认，不阻塞返回）。
  - 事务注解 `@Transactional(rollbackFor = Exception.class)`。
- **可能错误码**：
  - `10001 PARAM_ERROR`：DTO 校验失败（`message` 为具体校验文案）。
  - `10002 NOT_LOGIN`：未登录。
  - `20003 PUBLISH_LIMIT`：新账号当日发布超限。
  - `90001 SYSTEM_ERROR`：其它未捕获异常统一由全局处理器返回（如卖家资料缺失等边界情况）。

#### 5. 编辑商品
- **方法与路径**：`PUT /api/v1/items/{id}`
- **鉴权**：需要登录，且只能改自己的商品
- **请求参数**：

| 位置 | 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| path | `id` | long | 是 | 商品 id |

- **请求体**（`ItemUpdateDTO`，**所有字段可选**，null = 不改该项）：

```json
{
  "title": "九成新自行车（可小刀）",
  "description": "刹车刚换过，送车锁。",
  "categoryId": 3,
  "conditionLevel": 2,
  "price": 199.00,
  "originalPrice": 899.00,
  "negotiable": 1,
  "stock": 1,
  "isUnique": 1,
  "images": ["http://.../new-cover.jpg"],
  "preferPointId": 8,
  "videoUrl": "http://.../v.mp4"
}
```

| 字段 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| `title` | string | 否 | `@Size(max=80)`；有值才改，且 `trim()` |
| `description` | string | 否 | `@Size(max=2000)`；非 null 才改（空串视为改成空） |
| `categoryId` | long | 否 | 无校验 |
| `conditionLevel` | int | 否 | `@Min(1)@Max(5)` |
| `price` | decimal | 否 | `@DecimalMin("0.01")`、`@DecimalMax("99999.99")` |
| `originalPrice` | decimal | 否 | 无校验 |
| `negotiable` / `stock` / `isUnique` | int | 否 | 无校验 |
| `images` | string[] | 否 | `@Size(max=9)`；**只有非 null 且非空才生效**，生效时整组替换且 `coverUrl=images[0]` |
| `preferPointId` / `videoUrl` | long / string | 否 | 非 null 才改 |

- **响应示例**：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "itemId": 1024,
    "status": 2,
    "statusText": "在售"
  },
  "traceId": "trace-xxx"
}
```

- **业务规则 / 校验**：
  - 商品不存在 → `ITEM_NOT_FOUND`；不是本人 → `ITEM_NOT_OWNER`；**已售出（status=4）不能编辑** → `ITEM_SOLD`，消息「商品已售出，不能再改价格和标题」。
  - 只更新 DTO 中非 null（`title` 为有值文本）的字段，其余保持原值（`updateById` 按 NOT_NULL 策略提交）。
  - 标题/描述是否变化：`newTitle` 与 `newDescription` 分别与库中值比较；任一变化即 `textChanged=true`。
  - **编辑不改状态**：`newStatus` 始终取原状态；机审已移除，`textChanged` 只把 `auditResult` 置为 1，不置状态。
  - 事务提交后同步 ES 索引并清 Redis 详情缓存；调用 `itemReviewService.onContentMaybeChanged(itemId, textChanged)` —— 在售期间改标题/描述会重新进入运营「上架审核」页，只改价格/库存/图片不重新入队。
  - 响应中的 `status/statusText` 是**编辑前的原状态**（编辑不改变状态）。
- **可能错误码**：
  - `10001 PARAM_ERROR`、`10002 NOT_LOGIN`、`30001 ITEM_NOT_FOUND`、`30005 ITEM_NOT_OWNER`、`30002 ITEM_SOLD`。

- **请求参数**：

| 位置 | 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| path | `id` | long | 是 | 商品 id |

- **请求体**：无

```json
{

  "message": "ok",

}
```

- **业务规则 / 校验**：

#### 7. 重新上架
- **方法与路径**：`POST /api/v1/items/{id}/relist`
- **鉴权**：需要登录，且只能操作自己的商品
- **请求参数**：

| 位置 | 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| path | `id` | long | 是 | 商品 id |

- **请求体**：无
- **响应示例**：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "itemId": 1024,
    "status": 2,
    "statusText": "在售",
    "expireAt": "2026-11-06 12:00:00"
  },
  "traceId": "trace-xxx"
}
```

> 限时关闭（`validity-enabled=false`）时 `expireAt=null`，因 `non_null` 策略该字段不会出现在 JSON 中。

- **业务规则 / 校验**：
  - **只允许 `status=5`（已下架）或 `status=7`（已过期）**，其余状态一律抛 `ITEM_STATUS_ERROR`，消息「只有「已下架」或「已过期」的商品可以重新上架」。特别地：4 已售出、6 审核未通过、8 违规下架都不能走这里。

  - 不重新审核内容、不占「每日发布上限」额度；重新上架算一次新曝光（刷新 `publishedAt`）。
  - 事务提交后同步 ES + 清缓存；并调用 `onItemLiveOptimistic(itemId, TYPE_RELIST)` 重新进入「上架审核」队列。
- **可能错误码**：
  - `10002 NOT_LOGIN`、`30001 ITEM_NOT_FOUND`、`30005 ITEM_NOT_OWNER`、`30006 ITEM_STATUS_ERROR`。

- **业务规则 / 校验**：

### 3.3 搜索（`SearchController`，2 个）

基路径 `/api/v1/search`，围绕 ES 索引 `ershou_item` 的运维/诊断接口。商品关键词检索本身不在这里，走 `GET /api/v1/items?keyword=...`（见接口 1）。

#### 10. 搜索索引状态
- **方法与路径**：`GET /api/v1/search/status`
- **鉴权**：公开（白名单精确放行该路径）
- **请求参数**：无
- **请求体**：无
- **响应示例**：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "enabled": true,
    "indexName": "ershou_item",
    "esAvailable": true,
    "watermark": "2026-10-30T02:00:00Z",
    "reindexing": false,
    "indexExists": true,
    "docCount": 128,
    "onSaleCount": 37
  },
  "traceId": "trace-xxx"
}
```

- **业务规则 / 校验**：
  - `enabled`：`ershou.search.enabled`；`esAvailable`：ES 未熔断且客户端存在；`lastError`：最近一次失败（成功后清空）；`watermark`：Redis `ershou:item:index:watermark` 的 ISO Instant，缺失时按「当前时间 - 回看窗口」计算；`reindexing`：是否有全量重建在执行。
  - 索引存在时额外返回 `indexExists`、`docCount`（索引内全部状态文档数）、`onSaleCount`（`status=2` 文档数，即公开检索可见条数）；ES 查询异常时返回 `esError` 而不是失败。
  - `indexName` 默认 `ershou_item`（`SearchProperties`）。
- **可能错误码**：
  - 无业务错误码（ES 不可用也返回 `code=0`，通过字段体现）。

#### 11. 全量重建商品索引
- **方法与路径**：`POST /api/v1/search/reindex`
- **鉴权**：需运营权限（Controller 内 `adminAuthService.requireAdminId()`：先校验登录，再校验 `role_flags & 8` 或管理员白名单）
- **请求参数**：

| 位置 | 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| query | `sync` | boolean | 否 | 默认 `false`（后台异步）；`true` 同步等待重建完成后返回结果 |

- **请求体**：无
- **响应示例（`sync=true` 同步重建）**：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "indexName": "ershou_item",
    "analyzer": "ik_max_word+syn",
    "indexed": 128,
    "visible": 37,
    "docCount": 128,
    "rebuilt": true
  },
  "traceId": "trace-xxx"
}
```

- **响应示例（默认异步）**：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "started": true,
    "message": "索引重建已在后台开始，可用 /api/v1/search/status 查看结果"
  },
  "traceId": "trace-xxx"
}
```

- **业务规则 / 校验**：
  - **清空重建**：先删除现有索引（存在时）再按 MySQL 全量分页重建，能清掉「绕过写路径」产生的幽灵文档；重建期间搜索短暂降级 MySQL LIKE。
  - 建索引是幂等的：索引存在时先用 `POST /{index}/_analyze` 拿 `ershou_index` 分析器切「高等数学」验证可用性；不可用则删除重建。分词方案按优先级尝试：`ik_max_word+syn` → `ik_max_word` → `smartcn+syn` → `smartcn` → 内置 ngram；返回实际生效方案名（已有可用索引返回 `existing`）。
  - 索引结构：`number_of_shards=1`、`number_of_replicas=0`；字段含 `id/sellerId/schoolId/campusId/categoryId/categoryName/title/description/price/originalPrice/conditionLevel/negotiable/stock/isUnique/status/sellerType/coverUrl/publishedAt/updatedAt/viewCount/favCount`；`title` 额外有 `raw` keyword 子字段；`publishedAt/updatedAt` 存 epoch millis；`categoryName/title/description` 用 `ershou_index`（索引期）与 `ershou_search`（检索期）分析器。
  - 全量重建按 id 升序分批（`bulkSize` 默认 200）bulk 写入，完成后显式 refresh，再统计 `docCount` 与 `visible`（status=2）；并把增量水位回拨到「开始时间 - 60 秒」，让重建期间的变更下一轮再同步（upsert 幂等）。
  - 异步模式用单线程执行器串行执行，`AtomicBoolean` 防重复触发；已在执行时返回 `{started:false, message:"已有重建任务在执行中"}`。
  - 索引里保存**所有状态**的商品，公开检索固定过滤 `status=2`，所以状态流转只 upsert、不删文档。
- **可能错误码**：
  - `10002 NOT_LOGIN`：未登录。
  - `10003 NO_PERMISSION`：已登录但不是运营，消息「需要运营人员权限」。
  - `90001 SYSTEM_ERROR`：ES 不可用（`IllegalStateException` 被全局处理器兜底），或索引删除/创建失败。

### 3.4 文件（`FileController`，1 个）

#### 12. 上传图片
- **方法与路径**：`POST /api/v1/files/upload`
- **鉴权**：需要登录（拦截器 + Controller 内 `StpUtil.checkLogin()`）
- **请求参数**：

| 位置 | 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| form-data | `file` | file | 是 | 图片文件，字段名必须是 `file` |
| form-data | `biz` | string | 否 | 业务目录，默认 `item`；源码注释约定取值 `item / avatar / chat / consign / report` |

- **请求体**（`multipart/form-data`，非 JSON）：

```text
file=<binary image>
biz=item
```

- **响应示例**：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "url": "http://127.0.0.1:9010/ershou/item/2026/10/6f1c2a9d8b7e4c33a1b2c3d4e5f60718.jpg"
  },
  "traceId": "trace-xxx"
}
```

- **业务规则 / 校验**（`MinioFileStorageService`，`mode=minio` 默认）：
  - 空文件 → `PARAM_ERROR`「请选择要上传的图片」。
  - 大小上限 `ershou.storage.max-size-mb`（默认 5MB）→ 超限 `PARAM_ERROR`「图片不能超过 XMB」；Spring 的 `max-file-size` 同为 5MB，触发 `MaxUploadSizeExceededException` 时全局处理器返回 `PARAM_ERROR`「图片超过 5MB 限制」。
  - 扩展名只允许 `.jpg / .jpeg / .png / .webp` → 否则 `PARAM_ERROR`「仅支持 jpg / png / webp 格式」。
  - 统一压缩并转 jpg：`outputQuality=0.8`；长边超过 `image-max-edge`（默认 1280）时等比缩放到 1280，否则原尺寸；无法解析的图片 → `PARAM_ERROR`「图片无法解析，请换一张」。
  - 对象 key 规则：`{dir}/{yyyy}/{MM}/{uuid32}.jpg`，其中 `dir = biz` 去掉所有非字母字符，`biz` 为空/空白用 `common`。
  - 上传时 `Content-Type: image/jpeg`；返回 URL 为 `ershou.storage.public-base-url + "/" + key`（默认 `http://127.0.0.1:9010/ershou/...`）。
  - 启动时 `@PostConstruct` 检查 bucket 是否存在，不存在则创建并设置「公开只读」bucket policy；初始化失败只记日志（之后上传会返回 90003）。
  - MinIO 异常统一转 `STORAGE_ERROR`（90003）。
  - `mode=local` 时改用 `LocalFileStorageService`：只校验空文件，不压缩、不校验大小与扩展名；落盘到 `ershou.storage.local-path`（默认 `./upload/`），返回 `local-url-prefix + 相对路径`，并通过 `WebMvcConfig` 的 `/static/**` 静态映射访问。
- **可能错误码**：
  - `10001 PARAM_ERROR`（空文件 / 超大小 / 格式不支持 / 图片无法解析 / multipart 超限）。
  - `10002 NOT_LOGIN`。
  - `90003 STORAGE_ERROR`（MinIO 写入失败、本地保存失败）。

| 0 | 草稿 | 表默认值；当前发布流程不会产生 | —（以源码为准） |
| 1 | 审核中 | 违规商品二次申请上架（`apply-relist`，8→1）；运营审核工作台通过→2，驳回→6 | 编辑（不改状态） |
| 2 | 在售 | 发布直接进入（机审已移除）；重新上架（5/7→2）；锁库释放（3→2） | 编辑 / 下架 / 被锁库 |
| 3 | 已锁定 | 下单锁库存时置为 3（`ItemMapper.lockStock`，锁 30 分钟），超时释放回 2 | 可下架：`offline` 只拒绝 `status=4`，已锁定商品被下架时置为 5 并关闭挂单 |
| 4 | 已售出 | 成交（`markSold`，2/3→4，同时 `stock=0`） | **不能编辑**（`ITEM_SOLD`）、不能下架 |
| 5 | 已下架 | 卖家主动下架（`offline`）；运营「上架审核」页的「下架」处置（`downlist`） | 可重新上架（5→2） |
| 6 | 审核未通过 | 运营审核驳回（`rejectAudit`，仅 1→6）；机审移除后正常发布不会产生 | 可编辑，但不能直接 relist |
| 7 | 已过期 | 定时任务把超过 `expire_at` 的在售商品置为 7（`validity-enabled=false` 时任务跳过） | 可重新上架（7→2） |
| 8 | 违规下架 | 运营强制下架（`forceOffline`，1/2/3/6→8） | 不能 relist，只能 `apply-relist` 二次申请（8→1） |

补充说明：

- 新增商品时 `published_at=now`；重新上架会刷新 `published_at`，让商品重新出现在 `latest` 列表前部。
- `expire_at` 默认 = 发布/重新上架时间 + `valid-days`（7 天）；`ershou.item.validity-enabled=false` 时为 NULL（永久有效）。
- 机器审核（关键词机审）已移除，`CONTENT_VIOLATION(50001)` 仅作为历史错误码保留，本模块不再抛出。

### 5.2 搜索模块 `module/search`

| 类 | 职责 / 关键点 |

| `service/ItemIndexService` | 建索引/映射/分词方案回退、启动初始化、每 2 分钟按 `updated_at` 增量兜底、`syncById/syncByIds/deleteById`、全量清空重建（同步/异步）、`status()` |

- **Elasticsearch 8**：`RestClient`（手写 DSL 检索）与 `ElasticsearchClient`（索引管理、bulk、count）；索引名 `ershou_item`；中文分词优先 IK（`ik_max_word`/`ik_smart`）+ 查询期 `synonym_graph`（`analysis-ik/synonyms.txt`），缺失时退 `smartcn`，最后内置 ngram。
