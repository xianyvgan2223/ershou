# 05 · 单体接口：私聊 IM（REST + WebSocket）

> 代码位置：`ershou-server`（Spring Boot 3.3.5 / MyBatis-Plus 3.5.9 / Sa-Token 1.39.0 / JDK21）。
> 模块包：`com.ershou.campus.module.chat`。
> 基础路径：**`/api/v1/chat`**；WebSocket 路径：**`/ws/chat`**（不在 `/api` 前缀下）。
> 涉及表：`chat_session`（会话）、`chat_message`（消息）。
> 本文所有接口、字段、错误码均来自当前源码；源码未体现之处标注“以源码为准”。

---

## 1. 模块概览

| 项 | 说明 |
| --- | --- |
| REST 基础路径 | `/api/v1/chat`（`ChatController` 上 `@RequestMapping("/api/v1/chat")`） |
| WebSocket 地址 | `ws://<host>:8080/ws/chat?token=<token>`（`ChatWebSocketConfig`，端口以 `server.port` 为准，默认 8080） |
| 鉴权 | REST 全部需要登录：`SaTokenConfig` 只放行 `/api/v1/auth/**`、商品读、用户主页等白名单，**`/api/v1/chat/**` 不在白名单**，由 `SaInterceptor` 调 `StpUtil.checkLogin()`；WebSocket 由 `ChatHandshakeInterceptor` 自行校验 token |
| 登录凭证 | 请求头 `Authorization: Bearer <token>`；WebSocket 可用 `?token=xxx` 或同一个 `Authorization` 头 |
| 返回结构 | `Result<T> = {code, message, data, traceId}`，成功 `code=0`；WebSocket 帧**不是** `Result` 包装 |
| 分页 | 聊天模块**没有分页接口**；会话/消息均返回 `List`。`PageResult<T>={total,pageNum,pageSize,records}` 在本模块未使用 |
| 序列化 | `spring.jackson.default-property-inclusion=non_null`：**值为 null 的字段不会出现在 JSON 里**；`LocalDateTime` 按 ISO 输出（如 `2026-10-30T12:00:00`） |
| 在线状态 | Redis key `ershou:chat:online:{userId}`，TTL 90 秒，连接建立 / 心跳 `ping` 时刷新 |
| 未读快照 | Redis Hash `ershou:chat:unread:{userId}`，field=sessionId，value=未读数；**DB 为权威**，Redis 仅作顶栏红点快速读取 |
| 跨实例推送 | Redis Pub/Sub 频道 `ershou:chat:channel:msg`，实例 id 用于跳过自己发出的回声 |
| 配置前缀 | `ershou.chat.*`（`ChatProperties`）；聊天正文密钥 `ershou.crypto.chat-key`（`ContentCipher`） |

### 1.1 统一返回与错误处理

- 业务异常 `BizException` 由 `GlobalExceptionHandler` 转成 `Result.fail(code, message)`，**HTTP 状态码通常仍是 200**。
- 未登录抛 `NotLoginException` → `10002`。
- `@Valid` 参数校验失败 → `10001`（message 取字段校验注解的提示语）。
- 未捕获异常 → `90001`；`traceId` 取自 MDC。

### 1.2 聊天错误码（`ResultCode` 70001–70007）

| 枚举 | code | 默认 message | 触发点 |
| --- | --- | --- | --- |
| `CHAT_SELF` | 70001 | 不能和自己私聊 | 从自己发布的商品发起会话 |
| `CHAT_NOT_FOUND` | 70002 | 会话不存在或无权访问 | 会话 id 为空 / 不存在 / 不是参与者（不区分“不存在”与“非成员”，避免探测他人会话 id） |
| `CHAT_LIMIT` | 70003 | 今日私聊条数已达上限（新账号限制），明天再来吧 | 新号每日限额（默认关闭） |
| `CHAT_CONTENT_INVALID` | 70004 | 消息内容不合法 | 内容为空 / 文本超长 |
| `CHAT_SEND_FAILED` | 70005 | 消息发送失败，请重试 | WebSocket 发送时非业务异常的兜底 |
| `CHAT_BLOCKED` | 70006 | 你们之间已拉黑，无法继续私聊 | 任一方向存在拉黑 |
| `CHAT_RECALL_DENIED` | 70007 | 只能撤回自己 2 分钟内发送的消息 | 非发送方 / 超时 |

其它会出现的通用码：`10001`（参数校验）、`10002`（未登录）、`30001`（商品不存在）、`90001`（系统异常）。

## 2. 数据模型简表

DDL 见 `sql/schema.sql`。

### 2.1 `chat_session`（会话）

`user_a < user_b` + `item_id` 上有唯一索引 `uk_session_pair_item`：同一对人 + 同一件商品只有一条会话。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT PK AUTO | 会话 id |
| `user_a` | BIGINT NOT NULL | 较小的用户 id |
| `user_b` | BIGINT NOT NULL | 较大的用户 id |
| `item_id` | BIGINT NULL | 来源商品；从商品详情发起会话时必填 |
| `last_msg_id` | BIGINT NULL | 最后一条消息 id |
| `last_msg_text` | VARCHAR(120) NULL | 会话列表预览（文本截断到 `previewLength=60`，图片为 `[图片]`，撤回为 `[已撤回]`） |
| `last_msg_at` | DATETIME NULL | 最后消息时间，会话列表按它倒序 |
| `unread_a` / `unread_b` | INT NOT NULL DEFAULT 0 | 各自的未读数，消息落库时**条件自增** |
| `risk_level` | TINYINT NOT NULL DEFAULT 0 | 会话风险等级 0/1/2/3 |
| `status` | TINYINT NOT NULL DEFAULT 1 | 1=允许发送（`canSend` 判据）；**不表示删除** |
| `deleted_a` / `deleted_b` | TINYINT NOT NULL DEFAULT 0 | 每用户软删除标记（“删除聊天记录”只删自己这一侧） |
| `deleted_a_at` / `deleted_b_at` | DATETIME NULL | 各自删除时间 |
| `created_at` / `updated_at` | DATETIME | 自动维护 |

### 2.2 `chat_message`（消息）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT PK AUTO | 消息 id（历史消息游标就用它） |
| `session_id` | BIGINT NOT NULL | 所属会话 |
| `sender_id` / `receiver_id` | BIGINT NOT NULL | 发送方 / 接收方 |
| `item_id` | BIGINT NULL | 商品卡片关联商品（取会话的 `item_id`） |
| `msg_type` | TINYINT NOT NULL DEFAULT 1 | 1=文本 2=图片 3=位置 4=商品卡片 5=面交单卡片 6=系统消息 |
| `content` | TEXT NOT NULL | **文本消息存 AES-GCM 密文**（`v1:base64(iv||密文||tag)`）；图片/卡片类存原文 |
| `risk_level` | TINYINT NOT NULL DEFAULT 0 | 0 正常 / 1 提醒 / 2 可疑 / 3 高危 |
| `blocked` | TINYINT NOT NULL DEFAULT 0 | 是否被风控拦截；拦截消息只对发送方可见 |
| `recalled` | TINYINT NOT NULL DEFAULT 0 | 是否已撤回（发送方限时撤回，撤回后双方都取不到原文） |
| `created_at` | DATETIME NOT NULL | 发送时间，撤回时限以它为基准 |

## 3. REST 接口（`ChatController`，共 12 个）

### 1. 我的会话列表
- **方法与路径**：`GET /api/v1/chat/sessions`
- **鉴权**：需要登录
- **请求参数**：

  | 位置 | 参数 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- | --- |
  | query | `includeDeleted` | boolean | 否 | 默认 `false`；`true` 时把“我删过的会话”也返回 |

- **请求体**（如有）：无
- **响应示例**：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": [
      {
        "id": 12,
        "lastMsgId": 9031,
        "peerId": 1002,
        "peerName": "小林",
        "peerAvatar": "https://cdn.example.com/a.png",
        "peerCreditScore": 92,
        "peerIdentityFlag": 0,
        "peerOnline": true,
        "itemId": 501,
        "itemTitle": "九成新显示器",
        "itemCover": "https://cdn.example.com/i.jpg",
        "itemPrice": 260.00,
        "itemStatus": 2,
        "itemStatusText": "在售",
        "myRole": "buyer",
        "peerRole": "seller",
        "blockedByMe": false,
        "blockedByPeer": false,
        "canSend": true,
        "lastMsgText": "明天下午三点可以吗",
        "lastMsgAt": "2026-10-30T11:20:00",
        "unread": 2,
        "riskLevel": 0,
        "createdAt": "2026-10-29T20:10:00"
      }
    ],
    "traceId": "a1b2c3"
  }
  ```
- **业务规则 / 校验**：
  - 只查 `user_a = 我 OR user_b = 我`，按 `last_msg_at DESC, id DESC` 排序。
  - 默认剔除 `deletedFor(me)=1` 的会话；`includeDeleted=true` 时保留。
  - 批量补对方资料（`UserService.mapByIds`：昵称/头像/信用分/身份标识）和商品卡片（`itemMapper.selectBatchIds`）。
  - `peerOnline` 读 Redis `ershou:chat:online:{peerId}` 是否存在（Redis 异常按离线处理）。
  - 拉黑关系一次查全：`blockedByMe = 我拉黑对方`、`blockedByPeer = 对方拉黑我`。
  - `canSend = 双向均未拉黑 且 status 为 null 或 1`。
  - `myRole`/`peerRole` 相对来源商品而言：商品卖家是 `seller`，另一方 `buyer`；商品已删除时 `itemTitle="商品已删除"`、角色为 null。
  - 返回前用 DB 未读数回写 Redis Hash，做缓存自愈（Redis 失败只告警）。
- **可能错误码**：`10002`（未登录）、`90001`（未预期异常）。

### 2. 从商品发起会话
- **方法与路径**：`POST /api/v1/chat/sessions`
- **鉴权**：需要登录
- **请求参数**：

  | 位置 | 参数 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- | --- |
  | body | `itemId` | Long | 是 | 来源商品 id（`@NotNull`） |

- **请求体**（如有）：
  ```json
  {
    "itemId": 501
  }
  ```
- **响应示例**：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": {
      "id": 12,
      "lastMsgId": null,
      "peerId": 1002,
      "peerName": "小林",
      "peerOnline": false,
      "itemId": 501,
      "itemTitle": "九成新显示器",
      "itemPrice": 260.00,
      "itemStatus": 2,
      "itemStatusText": "在售",
      "myRole": "buyer",
      "peerRole": "seller",
      "blockedByMe": false,
      "blockedByPeer": false,
      "canSend": true,
      "unread": 0,
      "riskLevel": 0,
      "createdAt": "2026-10-30T12:00:00"
    },
    "traceId": "a1b2c3"
  }
  ```
- **业务规则 / 校验**：
  - 商品不存在 → `30001`。
  - 商品卖家就是自己 → `70001`（不能和自己私聊）。
  - 任一方拉黑另一方 → `70006`。
  - 存储时 **`user_a = min(我, 卖家)`、`user_b = max(...)`**；新会话 `unread_a=unread_b=0`、`risk_level=0`、`status=1`、`deleted_a=deleted_b=0`，`last_msg_at=now()`（新会话排最前）。
  - 已存在同一对人 + 同一商品则复用；并发插入撞唯一索引时回查已存在记录，查不到回 `90001`（“会话创建失败，请重试”）。
  - 若该会话已被**我**软删除，视为“重新开启”，调 `restoreDeleted` 撤销双方删除标记（会同时清掉双方标记）。
  - 返回值是当前用户视角的 `ChatSessionVO`。
- **可能错误码**：`10001`（itemId 缺失/校验失败）、`30001`、`70001`、`70006`、`90001`。

### 4. 删除聊天记录
- **方法与路径**：`DELETE /api/v1/chat/sessions/{id}`
- **鉴权**：需要登录
- **请求参数**：

  | 位置 | 参数 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- | --- |
  | path | `id` | Long | 是 | 会话 id |

- **请求体**（如有）：无
- **响应示例**：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": null,
    "traceId": "a1b2c3"
  }
  ```
- **业务规则 / 校验**：
  - **每用户软删除**：只把“我这一侧”的 `deleted_a` 或 `deleted_b` 置 1，并记录 `deleted_*_at`；对方列表完全不受影响。
  - 同一条 SQL 里把**我这一侧的未读数归零**（避免“列表没有、红点还在”）。
  - 同时删除 Redis 未读 Hash 中该会话字段（Redis 失败只告警，不影响主流程）。
  - 幂等：已是删除状态直接返回成功。
  - **不物理删除任何消息行**（对方还要看历史）。
  - 对方再发消息时，发送路径会自动 `restoreDeleted`，会话重新出现在双方列表。
- **可能错误码**：`70002`、`10002`。

### 5. 批量删除聊天记录
- **方法与路径**：`POST /api/v1/chat/sessions/batch-delete`
- **鉴权**：需要登录
- **请求参数**：

  | 位置 | 参数 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- | --- |
  | body | `ids` | List\<Long\> | 是 | 要删除的会话 id 列表（`@NotNull`） |

- **请求体**（如有）：
  ```json
  {
    "ids": [12, 13, 14]
  }
  ```
- **响应示例**（复用了运营模块的 `BatchAuditResultVO`，**不是** `PageResult`）：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": {
      "success": 2,
      "failed": 1,
      "failures": [
        { "id": 14, "reason": "会话不存在或无权访问" }
      ]
    },
    "traceId": "a1b2c3"
  }
  ```
- **业务规则 / 校验**：
  - 先过滤 `null`、去重；去重后为空 → `10001`（“请先勾选要删除的会话”）。
  - 逐条独立处理，单条失败不整批回滚；失败原因来自 `BizException` 的 message 或 `"删除失败：" + e.getMessage()`。
  - 每条复用单删逻辑（软删除 + 未读归零 + 清 Redis 字段）。
  - 返回值：`success`（成功数）、`failed`（失败数）、`failures[]`（`{id, reason}`）。
- **可能错误码**：`10001`（ids 为空 / 校验失败）、`10002`；单条失败以 `failures` 明细体现（典型为 `70002`）。

### 6. 历史消息
- **方法与路径**：`GET /api/v1/chat/sessions/{id}/messages`
- **鉴权**：需要登录
- **请求参数**：

  | 位置 | 参数 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- | --- |
  | path | `id` | Long | 是 | 会话 id |
  | query | `beforeId` | Long | 否 | 往前翻历史：只取 `id < beforeId` 的消息 |
  | query | `afterId` | Long | 否 | 断线补拉：只取 `id > afterId` 的消息 |
  | query | `size` | Integer | 否 | 条数；缺省/小于 1 用配置 `historySize`（默认 20），上限 `maxHistorySize`（默认 50） |

- **请求体**（如有）：无
- **响应示例**（**时间正序**，无分页包装）：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": [
      {
        "id": 9030,
        "sessionId": 12,
        "senderId": 1002,
        "receiverId": 1001,
        "msgType": 1,
        "content": "在的，还卖",
        "riskLevel": 0,
        "mine": false,
        "recalled": false,
        "createdAt": "2026-10-30T11:18:00"
      },
      {
        "id": 9031,
        "sessionId": 12,
        "senderId": 1001,
        "receiverId": 1002,
        "msgType": 1,
        "content": "明天下午三点可以吗",
        "riskLevel": 0,
        "mine": true,
        "recalled": false,
        "createdAt": "2026-10-30T11:20:00"
      }
    ],
    "traceId": "a1b2c3"
  }
  ```
- **业务规则 / 校验**：
  - 必须是我参与的会话，否则 `70002`。
  - `beforeId` 与 `afterId` **互斥**，同时传 → `10001`（“beforeId 与 afterId 不能同时使用”）。
  - 查询条件：`session_id = ?` **且** `(blocked = 0 OR sender_id = 我)`——被风控拦截的消息只对发送方可见。
  - 先按 `id DESC` 取 `limit` 条，再反转成**时间正序**返回。
  - `afterId` 场景取的是“比它新的最新 limit 条”，一次追上最新进度。
  - 文本消息解密后返回；解密失败返回 `[消息内容不可用]`；非文本（图片/卡片）原样返回。
  - 已撤回消息 `recalled=true` 且 `content=""`（发送方也不下发原文）。
  - `mine = sender_id == 当前用户`；`clientMsgId` 在历史查询中为 null（不返回）。
  - `riskWarning` 字段当前代码未赋值（机审已移除），实际不会出现在 JSON 中。
- **可能错误码**：`70002`、`10001`、`10002`。

### 7. 发送消息（REST 兜底通道）
- **方法与路径**：`POST /api/v1/chat/messages`
- **鉴权**：需要登录
- **请求参数**：

  | 位置 | 参数 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- | --- |
  | body | `sessionId` | Long | 是 | 会话 id（`@NotNull`） |
  | body | `msgType` | Integer | 否 | 默认 1；1=文本 2=图片（图片时 `content` 为图片 URL） |
  | body | `content` | String | 否 | 消息内容；`@Size(max=500)`；文本不能为空 |
  | body | `clientMsgId` | String | 否 | 客户端本地消息 id，服务端 ACK 时原样带回 |

- **请求体**（如有）：
  ```json
  {
    "sessionId": 12,
    "msgType": 1,
    "content": "明天下午三点可以吗",
    "clientMsgId": "c-1730000000000"
  }
  ```
- **响应示例**：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": {
      "id": 9031,
      "sessionId": 12,
      "senderId": 1001,
      "receiverId": 1002,
      "msgType": 1,
      "content": "明天下午三点可以吗",
      "riskLevel": 0,
      "mine": true,
      "recalled": false,
      "clientMsgId": "c-1730000000000",
      "createdAt": "2026-10-30T11:20:00"
    },
    "traceId": "a1b2c3"
  }
  ```
- **业务规则 / 校验**：
  - 会话必须存在且我是参与者，否则 `70002`。
  - **双向拉黑拦截**：任一方拉黑另一方 → `70006`（被拉黑的人也不能继续发）。
  - `msgType` 为空按 1；`content` 先 `trim`，为空 → `70004`。
  - 文本消息长度上限为 `ershou.chat.max-text-length`（默认 **500**），超限 → `70004`；DTO 的 `@Size(max=500)` 会先触发 `10001`。
  - 新号每日限额：`ershou.chat.daily-limit-enabled` **默认 false（不生效）**。开启后，注册 `newUserDays`（默认 7）天内的用户每日最多 `sys_user.chat_limit` 条（为 null 时 20），超限 `70003`；计数 Redis key `ershou:limit:chat:{userId}:{yyyyMMdd}`，过期到当日 23:59:59。
  - **关键词机审已移除**：消息直接放行，`risk_level` 恒为 0、`blocked` 恒为 0。
  - 文本正文用 `ContentCipher` 做 **AES/GCM** 加密后落库，格式 `v1:base64(iv||密文||tag)`（IV 12 字节、tag 128 位、密钥为 `SHA-256(chat-key)` 前 16 字节）；图片/其它类型存原文。
  - 更新会话：`last_msg_id`、`last_msg_text`（文本按 `previewLength=60` 截断加 `…`；图片 `[图片]`；其它 `[消息]`）、`last_msg_at=now`。
  - 接收方此前删过会话 → `restoreDeleted` 自动恢复（否则消息落库却永远看不到）。
  - 接收方未读 +1（DB 条件自增 `unread_a`/`unread_b` + Redis Hash 自增，Redis 失败不影响）。
  - 落库成功后推送：给对方发 `message` 事件（接收方视角的 `ChatMessageVO`），本机直推 + Redis 广播。
  - 返回发送方视角的 `ChatMessageVO`（`mine=true`，带回 `clientMsgId`）。
  - **WebSocket 未连通时**用本接口兜底；若走 WS，同样逻辑，但成功回 `ack` 帧而非 `Result`。
- **可能错误码**：`10001`、`70002`、`70006`、`70004`、`70003`（限额开启且超限）、`10002`、`90001`。

### 8. 撤回消息
- **方法与路径**：`POST /api/v1/chat/messages/{id}/recall`
- **鉴权**：需要登录
- **请求参数**：

  | 位置 | 参数 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- | --- |
  | path | `id` | Long | 是 | 消息 id |

- **请求体**（如有）：无
- **响应示例**：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": {
      "id": 9031,
      "sessionId": 12,
      "senderId": 1001,
      "receiverId": 1002,
      "msgType": 1,
      "content": "",
      "riskLevel": 0,
      "mine": true,
      "recalled": true,
      "createdAt": "2026-10-30T11:20:00"
    },
    "traceId": "a1b2c3"
  }
  ```
- **业务规则 / 校验**：
  - 消息不存在 → `10001`（“消息不存在”）；会话不存在/非成员 → `70002`。
  - **仅发送方**可撤回，否则 `70007`。
  - **限时撤回**：以 `created_at` 判断，超过 `ershou.chat.recall-window`（默认 **2 分钟**）→ `70007`（“只能撤回 N 分钟内发送的消息”）。
  - 幂等：已撤回则直接返回当前视图，不报错。
  - 撤回只把 `chat_message.recalled` 置 1，**不删除消息行**；`toMessageVO` 中 `recalled=true`、`content=""`。
  - 若撤回的是会话最后一条，同步把 `chat_session.last_msg_text` 改为 `[已撤回]`。
  - 向对方推送 `recall` 事件（对方视角的 `ChatMessageVO`）。
- **可能错误码**：`10001`、`70002`、`70007`、`10002`。

### 10. 未读汇总
- **方法与路径**：`GET /api/v1/chat/unread`
- **鉴权**：需要登录
- **请求参数**：

  | 位置 | 参数 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- | --- |
  | — | 无 | — | — | 仅按当前登录用户统计 |

- **请求体**（如有）：无
- **响应示例**：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": {
      "total": 3,
      "sessions": {
        "12": 2,
        "13": 1
      }
    },

  }
  ```
- **业务规则 / 校验**：
  - 先查“我的会话”并**剔除我删过的会话**（删掉的会话不贡献红点）。

  - Redis 读写异常只告警，仍返回 DB 结果。
- **可能错误码**：`10002`、`90001`（极端情况）。

## 4. WebSocket

### 4.1 连接与握手鉴权

| 项 | 内容 |
| --- | --- |
| 地址 | `ws://<host>:8080/ws/chat?token=<Sa-Token token>`；也可以不传 query，改用请求头 `Authorization: Bearer <token>` |
| 注册条件 | `ershou.chat.enabled=true`（默认 true）。关闭后 `ChatWebSocketConfig.registerWebSocketHandlers` 直接 return，不注册 handler，前端退回 REST + 轮询 |
| 鉴权 | `ChatHandshakeInterceptor.beforeHandshake`：从 `?token=`（优先）或 `Authorization: Bearer` 取 token；为空或 `StpUtil.getLoginIdByToken(token)` 返回 null → 响应 **401** 并拒绝握手 |
| 身份注入 | 鉴权通过后把用户 id 写入 session 属性 `chatUserId`（Long），Handler 全程从这里取用户 |
| 跨域 | `setAllowedOriginPatterns("*")`；生产建议由 Nginx 同源反代 `/ws`（以部署配置为准） |
| 会话过期 | 握手后不再复检 token；token 失效/过期时已建立的连接不会因鉴权被断开（以源码为准） |

### 4.2 帧格式

- 传输：**原生 WebSocket + JSON 文本帧**（不是 STOMP）。
- 客户端 → 服务端：

  | `type` | 帧示例 | 说明 |
  | --- | --- | --- |
  | `ping` | `{"type":"ping"}` | 心跳；刷新在线 TTL（90s），回 `pong`（`{"ts": 时间戳}`）。建议 30 秒一次 |
  | `send` | `{"type":"send","sessionId":12,"msgType":1,"content":"hi","clientMsgId":"c-1"}` | 发送消息；`msgType` 缺省按 1；成功回 `ack` |
  | `read` | `{"type":"read","sessionId":12}` | 标记已读；回 `read-ack` |
  | 其它 | — | 回 `error`，code=`10001`，message=`不支持的消息类型：xxx` |

- 服务端 → 客户端（统一 `{"type": ..., "data": ...}`）：

  | `type` | 触发 | `data` 内容 |
  | --- | --- | --- |
  | `ready` | 连接建立 | `{userId, online:true, instanceId}` |
  | `pong` | 收到 `ping` | `{ts}` |
  | `ack` | `send` 成功 | 发送方视角的 `ChatMessageVO`（含 `clientMsgId`，用于把“发送中”替换为“已送达”） |
  | `message` | 有人给我发消息 | 接收方视角的 `ChatMessageVO`（`mine=false`） |
  | `read` | 对方标记已读 | `{sessionId, readerId}` |
  | `recall` | 对方撤回 | 对方视角的 `ChatMessageVO`（`recalled=true, content=""`） |
  | `read-ack` | 我的 `read` 帧处理成功 | `{sessionId}` |
  | `error` | 业务/系统异常、未知 type | `{clientMsgId, code, message}`（`clientMsgId` 可能为 null） |

- **错误帧示例**：
  ```json
  {"type":"error","data":{"clientMsgId":"c-1","code":70006,"message":"你们之间已拉黑，无法继续私聊"}}
  ```
- 业务异常（`BizException`）用其真实 `code/message`；非业务异常统一 `70005`（“消息发送失败，请重试”）。

### 4.3 推送机制

- `ChatPushService.push(userId, type, data)`：先**本机直推**（内存 `Map<userId, Set<WebSocketSession>>`，支持同一用户多连接），再 `publish` 到 Redis 频道 `ershou:chat:channel:msg`。
- 广播信封：`{instanceId, userId, type, data}`；`ChatRedisConfig` 订阅该频道，`onRemoteMessage` 跳过 `instanceId` 等于本实例的消息，避免回声，其余调 `pushLocal` 推给本机连接。
- 单条连接发送（`ready`/`pong`/`ack`/`read-ack`/`error`）走 `sendTo`，不广播。
- `WebSocketSession` 非线程安全：发送时 `synchronized (session)` 串行化；连接已关闭或异常只告警。
- 在线心跳：`register` 与 `ping` 都 `touch`，写 `ershou:chat:online:{userId}`，TTL `onlineTtl=90s`；**断线不主动删 key**，由 TTL 自然过期（避免刷新页面/多标签页互相踩）。
- 连接关闭 `afterConnectionClosed` 仅从本机内存集合移除；传输异常则关闭连接（`CloseStatus.NOT_ACCEPTABLE`）。

### 4.4 与 REST 的关系

- `send` 帧内部直接调 `ChatService.send(...)`，与 `POST /api/v1/chat/messages` **同一条业务链路**（拉黑、限额、长度、加密、落库、未读、推送完全一致）。
- 区别：WS 成功回 `ack` 帧，不返回 `Result`；WS 构造 DTO 时**不经过 Bean Validation**，`content` 长度由 `ChatService` 按配置（默认 500）校验。
- WS 不可用（未启用/断线/握手失败）时，前端应回退到 REST 发送 + 轮询会话/未读。

## 5. 枚举与常量

### 5.1 消息类型 `msgType`

以 `ChatMessage` 实体与 `sql/schema.sql` 为准；`ChatService` 只显式定义了前两个常量。

| 值 | 含义 | `ChatService` 常量 | 落库 content | 会话预览 |
| --- | --- | --- | --- | --- |
| 1 | 文本 | `MSG_TEXT = 1` | AES-GCM 密文（`v1:` 前缀） | 原文截断到 60 字 + `…` |
| 2 | 图片 | `MSG_IMAGE = 2` | 原文（图片 URL/数组） | `[图片]` |
| 3 | 位置 | 无 | 原文 | `[消息]` |
| 4 | 商品卡片 | 无 | 原文 | `[消息]` |
| 5 | 面交单卡片 | 无 | 原文 | `[消息]` |
| 6 | 系统消息 | 无 | 原文 | `[消息]` |

> 当前 Controller/WS 只透传 `msgType`，未对 3–6 做额外校验或特殊渲染；前端按类型自行展示。

### 5.2 风险等级 `risk_level`

| 值 | 含义 | 常量位置 |
| --- | --- | --- |
| 0 | 正常 | `ChatService.RISK_NONE = 0`；会话/消息默认值 |
| 1 | 提醒 | 实体注释（`ChatService` 未定义常量） |
| 2 | 可疑（弱提醒后放行） | `ChatService.RISK_REVIEW = 2`（private） |
| 3 | 高危（拦截） | `ChatService.RISK_BLOCK = 3`；`ChatRiskRecorder` 写 3 |

> **现状**：`ChatService.send` 已移除关键词机审，`riskLevel` 恒置 0、`blocked` 恒置 0，因此“高危拦截 / 接收方不可见 / riskWarning 弱提醒”在当前运行路径上不会触发。`ChatRiskRecorder.recordBlocked`（`REQUIRES_NEW` 独立事务留痕）保留但**未被任何代码调用**；`ChatMessageVO.riskWarning` 字段保留但未赋值。若要恢复机审，需在 `send` 中判定并调用 `ChatRiskRecorder`。
