## 模块概览

| 项 | 说明 |
| --- | --- |
| 基础路径 | `/api/v1`（Spring Boot 端口 `8080`） |
| 子路径 | `/api/v1/auth/**`、`/api/v1/users/**`、`/api/v1/schools/**` |
| 鉴权 | Sa-Token。登录后请求头 `Authorization: Bearer <token>`（`token-name=Authorization`、`token-prefix=Bearer`、`token-style=uuid`） |
| 会话 | Redis 存会话；`timeout=315360000`（10 年）、`active-timeout=-1`、`is-concurrent=true`（多端同时在线）、`is-share=false`（每次登录发新 token） |
| 公开接口 | `/api/v1/auth/**` 全部；`/api/v1/schools/**` 全部；`GET /api/v1/users/{id}/profile`（白名单见 `SaTokenConfig`） |
| 需登录 | 其余 `/api/v1/users/**`（`/me`、`/blocks`、拉黑/解除拉黑） |
| 运营权限 | 本模块**没有**运营接口；仅 `UserVO.isAdmin` 是运营身份标记（判定见 `AdminAuthService`：`role_flags & 8 != 0` 或命中 `ershou.admin.user-ids` 白名单） |
| 统一返回 | `Result<T> = {code, message, data, traceId}`，成功 `code=0`、`message="ok"`；`traceId` 来自 `MDC.traceId`（16 位 UUID 片段，同时回写响应头 `X-Trace-Id`） |
| 分页 | 本模块**没有分页接口**；`PageResult<T> = {total, pageNum, pageSize, records}` 仅作为全站约定列出，课程里用不到 |
| 空值序列化 | Jackson `default-property-inclusion: non_null`：值为 `null` 的字段**不会出现在 JSON 里**（下文的 `null` 只用于说明语义） |
| 时间字段 | 实体/VO 用 `LocalDateTime`，Spring Boot 默认按 ISO-8601 输出（如 `2026-10-30T10:00:00`）；以源码/序列化配置为准 |
| 全局异常 | `GlobalExceptionHandler` 把 `BizException` 转 `Result.fail(code, message)`；参数校验失败统一 `10001` + 具体校验文案；未登录 `10002`；其余异常 `90001`。**HTTP 状态码通常仍是 200**，看 `code` |

### 本模块涉及的 Redis Key（`RedisKeys`）

| Key | 用途 | TTL |
| --- | --- | --- |
| `ershou:sms:code:{phone}` | 短信验证码明文 | 5 分钟（登录成功后立即删除） |
| `ershou:sms:limit:{phone}:{yyyyMMdd}` | 同一手机号当日发送计数 | 首次自增时设为 1 天 |

## AuthController（`/api/v1/auth`）

> 路径整体在 Sa-Token 白名单内，三个接口都不需要登录态（见接口 3 的说明）。

### 1. 发送短信验证码
- **方法与路径**：`POST /api/v1/auth/sms-code`
- **鉴权**：公开
- **请求参数**（path/query）：无
- **请求体**：
  ```json
  {
    "phone": "13800138000"
  }
  ```
- **响应示例**：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": null,
    "traceId": "3f2a9c1d8e7b6a54"
  }
  ```
- **业务规则 / 校验**：
  - 入参 `SmsCodeDTO.phone`：`@NotBlank(message="请输入手机号")` + `@Pattern(regexp="^1[3-9]\\d{9}$", message="手机号格式不正确")`，不合法直接 `10001`。
  - 先做**每日上限**：`INCR ershou:sms:limit:{phone}:{yyyyMMdd}`，首次自增（返回值 =1）时把该 key 设 1 天 TTL；计数 `>10` 抛 `10004`，文案「今日验证码发送次数已达上限」。
  - 生成验证码：`ershou.sms.mock=true`（`application.yml` 默认 `true`）时固定为 `ershou.sms.mock-code`（默认 `"123456"`）；否则取 `ThreadLocalRandom.nextInt(100000, 1000000)` 的 6 位数字。
  - 验证码写入 `ershou:sms:code:{phone}`，**TTL 5 分钟**，覆盖写（重复请求会覆盖旧码）。
  - 真实发送尚未接入（代码里是 `// TODO 对接短信服务商`，只打日志），日志手机号用 `PhoneCrypto.mask` 脱敏。
  - 注意：代码注释写着「同号 60 秒一次」，但**实际实现只有每日 10 次上限**，没有 60 秒间隔限制——以源码为准。
  - 该接口不校验手机号是否已注册（注册与登录合并在接口 2）。
- **可能错误码**：`10001` PARAM_ERROR（手机号格式/必填）、`10004` RATE_LIMIT（当日超 10 次，文案自定义）、`90001` SYSTEM_ERROR（Redis 异常等）

### 2. 手机号验证码登录（轻注册，无实名）
- **方法与路径**：`POST /api/v1/auth/login`
- **鉴权**：公开
- **请求参数**（path/query）：无
- **请求体**：
  ```json
  {
    "phone": "13800138000",
    "code": "123456",
    "schoolId": 1,
    "campusId": 1,
    "deviceId": "device-fingerprint-001"
  }
  ```
  | 字段 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- |
  | `phone` | String | 是 | `@NotBlank` + `^1[3-9]\d{9}$` |
  | `code` | String | 是 | `@NotBlank`；与 Redis 中的验证码严格相等比较 |
  | `schoolId` | Long | 否 | 默认 `1`；**仅新注册时写入** |
  | `campusId` | Long | 否 | 默认 `1`；**仅新注册时写入** |
  | `deviceId` | String | 否 | 设备指纹；新注册写入，老用户登录时非空才覆盖 |
- **响应示例**：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": {
      "token": "e0f4c2a1b9d84f0e8a7c6b5d4e3f2a1b",
      "user": {
        "id": 12,
        "nickname": "同学8000",
        "phone": "138****8000",
        "schoolId": 1,
        "schoolName": "示例大学",
        "campusId": 1,
        "campusName": "东校区",
        "creditScore": 100,
        "creditLevel": 1,
        "identityFlag": 0,
        "publishLimit": 5,
        "chatLimit": 20,
        "newUser": true,
        "roleFlags": 1,
        "isAdmin": false,
        "createdAt": "2026-10-30T10:00:00"
      }
    },
    "traceId": "3f2a9c1d8e7b6a54"
  }
  ```
  > `avatar`、`shopName`、`shopIntro` 为 null，因 `non_null` 不会出现在 JSON 中。
- **业务规则 / 校验**：
  - **校验码**：取 `ershou:sms:code:{phone}`，为空或与入参不等 → `20001`（验证码错误或已过期）；比对成功后**立即 `DEL`**，即验证码一次性，不能复用。
  - **查用户**：`SELECT * FROM sys_user WHERE phone_hash = SHA256(phone)`（不查明文手机号）。
  - **新用户（查不到）即注册**：
    - `phone = AES/ECB/PKCS5Padding(phone)`，`phone_hash = SHA256(phone)`（密钥 `ershou.crypto.phone-key`，值见 `.env` 的 `PHONE_AES_KEY`）。
    - `nickname = "同学" + phone.substring(7)`，即「同学」+ 手机号后 4 位。
    - `schoolId`/`campusId` 取入参，DTO 默认 1，显式传 null 也回落 `1`（**不校验学校和校区是否存在/启用**）。
    - `role_flags=1`、`identity_flag=0`、`credit_score=100`、`credit_level=1`、`risk_score=0`、`device_account_count=1`、`publish_limit=5`、`chat_limit=20`、`status=1`；`created_at`/`updated_at` 由 DB 默认值写入。
  - **老用户**：`status == 3`（封禁）→ `20002`；否则更新 `last_login_at = now()`，`deviceId` 非空时一并覆盖；`status == 2`（限权）**不拦截**。
  - **发 token**：`StpUtil.login(userId)` 后取 `StpUtil.getTokenValue()`。Sa-Token 每个端登录发新 token、不共用，10 年有效期。
  - **返回**：`LoginVO {token, user}`，`user` 为 `UserVO`，`newUser` 标记本次是否新注册（前端据此引导完善资料）。
  - 老用户登录**不会**更新 `schoolId`/`campusId`（改学校走接口 5）。
- **可能错误码**：`10001`（DTO 校验失败）、`20001` SMS_CODE_ERROR、`20002` USER_BANNED、`90001` SYSTEM_ERROR

### 3. 退出登录
- **方法与路径**：`POST /api/v1/auth/logout`
- **鉴权**：公开（`/api/v1/auth/**` 在白名单内；携带 token 时注销对应会话，未携带也返回成功）
- **请求参数**（path/query）：无
- **请求体**：无
- **响应示例**：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": null,
    "traceId": "3f2a9c1d8e7b6a54"
  }
  ```
- **业务规则 / 校验**：
  - 直接调用 `StpUtil.logout()`：删除**当前请求 token** 对应的会话（Redis 中 `Authorization:login:token:*`）。
  - 因为 `is-share=false` + `is-concurrent=true`，只影响本端 token，其它设备仍在线。
  - 无入参校验，无业务查询。
- **可能错误码**：`90001` SYSTEM_ERROR（极端异常）

## UserController（`/api/v1/users`）

### 4. 当前登录用户信息
- **方法与路径**：`GET /api/v1/users/me`
- **鉴权**：需要登录
- **请求参数**（path/query）：无
- **请求体**：无
- **响应示例**：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": {
      "id": 12,
      "nickname": "同学8000",
      "avatar": "/static/avatar/default.png",
      "phone": "138****8000",
      "schoolId": 1,
      "schoolName": "示例大学",
      "campusId": 1,
      "campusName": "东校区",
      "creditScore": 100,
      "creditLevel": 1,
      "shopName": "8000 的小铺",
      "shopIntro": "校内当面交易，支持自提",
      "identityFlag": 1,
      "publishLimit": 5,
      "chatLimit": 20,
      "newUser": false,
      "roleFlags": 1,
      "isAdmin": false,
      "createdAt": "2026-10-30T10:00:00"
    },
    "traceId": "3f2a9c1d8e7b6a54"
  }
  ```
- **业务规则 / 校验**：
  - 取 `StpUtil.getLoginIdAsLong()` → `selectById`；用户记录不存在 → `10002`（未登录或登录已过期）。
  - 组装 `UserVO`：手机号解密后 `mask`（`前 3 位 + "****" + 后 4 位`），**解密异常被吞掉，phone 置 null**，不影响主流程。
  - 学校名/校区名走 `DictionaryCache`（Redis 缓存，`dict-ttl=1h`），不直查表。
  - `isAdmin`：`AdminAuthService.isAdmin(user)`，命中 `role_flags & 8` 或 `ershou.admin.user-ids` 白名单。
  - `newUser` 固定 `false`。
- **可能错误码**：`10002` NOT_LOGIN、`90001` SYSTEM_ERROR

### 5. 编辑我的资料（昵称 / 头像 / 学校校区 / 小铺信息）
- **方法与路径**：`PATCH /api/v1/users/me`
- **鉴权**：需要登录
- **请求参数**（path/query）：无
- **请求体**（字段全部可选，**只更新传了的字段**，`null` 表示不改）：
  ```json
  {
    "nickname": "小同学",
    "avatar": "/static/2026/10/avatar-abc.png",
    "schoolId": 2,
    "campusId": 3,
    "shopName": "小同学的小铺",
    "shopIntro": "周五下午在图书馆门口面交"
  }
  ```
  | 字段 | 类型 | 必填 | 校验 |
  | --- | --- | --- | --- |
  | `nickname` | String | 否 | `@Size(max=32, message="昵称不能超过 32 个字")`；trim 后为空 → `10001 "昵称不能为空"` |
  | `avatar` | String | 否 | `@Size(max=255, message="头像地址过长")`；trim 后空串 = 清空；非空必须以 `/`、`http://`、`https://` 开头，否则 `10001 "头像地址不合法，请重新上传"` |
  | `schoolId` | Long | 否 | 必须存在且 `status=1`，否则 `10001 "学校不存在或已停用"` |
  | `campusId` | Long | 否 | 必须存在且 `status=1`，否则 `10001 "校区不存在或已停用"`；且必须属于 `schoolId`（入参优先，未传则用当前学校），否则 `10001 "所选校区不属于该学校"` / `"换学校后请重新选择校区"` |
  | `shopName` | String | 否 | `@Size(max=64)`；trim 后空串 → 置 null（清空） |
  | `shopIntro` | String | 否 | `@Size(max=255)`；trim 后空串 → 置 null（清空） |
- **响应示例**：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": {
      "id": 12,
      "nickname": "小同学",
      "avatar": "/static/2026/10/avatar-abc.png",
      "phone": "138****8000",
      "schoolId": 2,
      "schoolName": "第二大学",
      "campusId": 3,
      "campusName": "南校区",
      "creditScore": 100,
      "creditLevel": 1,
      "shopName": "小同学的小铺",
      "shopIntro": "周五下午在图书馆门口面交",
      "identityFlag": 1,
      "publishLimit": 5,
      "chatLimit": 20,
      "newUser": false,
      "roleFlags": 1,
      "isAdmin": false,
      "createdAt": "2026-10-30T10:00:00"
    },
    "traceId": "3f2a9c1d8e7b6a54"
  }
  ```
- **业务规则 / 校验**：
  - 先 `getById`：用户不存在 → `10002`；`status == 3`（封禁）→ `20002`，封禁用户不能改资料。
  - **局部更新语义**：用 `LambdaUpdateWrapper` 拼 `SET`，`null` 字段完全跳过；`avatar` / `shopName` / `shopIntro` 传**空串**表示清空（显式 `set(null)`），所以不能改用 `updateById`（会忽略 null、清不掉值）。
  - 昵称 trim 后写库；小铺名、小铺简介同样 trim 后再决定写值还是置 null。
  - 学校 / 校区校验（`applySchoolCampus`）：
    - 两个都没传 → 跳过；
    - `schoolId` 传了：走 `DictionaryCache.school()`，必须存在且 `status=1`；
    - `campusId` 传了：走 `DictionaryCache.campus()`，必须存在且 `status=1`，并且 `campus.schoolId == 最终 schoolId`（最终学校 = 入参 `schoolId`，否则当前用户 `schoolId`）；
    - 只换学校不换校区：拿当前校区判断是否仍属于新学校，不属于 → `10001 "换学校后请重新选择校区"`（避免 `school_id`/`campus_id` 自相矛盾）。
  - **手机号不可改**（登录凭证、唯一索引）；**不收集真实姓名**，「姓名」即昵称。PRD BR-08。
  - 有任意字段变更才执行 `UPDATE`，然后重新查库返回最新 `UserVO`；方法带 `@Transactional(rollbackFor = Exception.class)`。
  - 前端头像必须来自上传接口产出的地址（`/static/...` 或 `http(s)://...`），后端只做前缀校验，不校验文件是否真实存在。
  - 代码中未对该字段做关键词机审（注释提到「复用商品那套关键词规则」，但当前实现里没有实际调用）——以源码为准。
- **可能错误码**：`10001` PARAM_ERROR（含多条自定义文案）、`10002` NOT_LOGIN、`20002` USER_BANNED、`90001` SYSTEM_ERROR

### 6. 用户主页（公开；登录后附带拉黑状态）
- **方法与路径**：`GET /api/v1/users/{id}/profile`
- **鉴权**：公开（`/api/v1/users/*/profile` 在 Sa-Token 白名单内；登录后自动带上查看者身份）
- **请求参数**（path/query）：
  | 位置 | 参数 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- | --- |
  | path | `id` | Long | 是 | 被查看的用户 id |
- **请求体**：无
- **响应示例**（已登录、查看他人）：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": {
      "id": 12,
      "nickname": "小同学",
      "avatar": "/static/avatar/default.png",
      "creditScore": 100,
      "creditLevel": 1,
      "identityFlag": 1,
      "shopName": "小同学的小铺",
      "schoolName": "示例大学",
      "campusName": "东校区",
      "createdAt": "2026-10-30T10:00:00",
      "status": 1,
      "onSaleCount": 3,
      "blocked": false,
      "blockedByPeer": false,
      "self": false
    },
    "traceId": "3f2a9c1d8e7b6a54"
  }
  ```
- **业务规则 / 校验**：
  - 用户不存在 → `10001`，文案「用户不存在」（注意不是 30001/40001 那类）。
  - **刻意不复用 `UserVO`**：主页是公开接口，**不返回手机号等任何联系方式**；被封禁（`status=3`）的账号主页**照样可访问**（历史交易与纠纷处理需要），由前端根据 `status` 提示。
  - `onSaleCount` = `item` 表 `seller_id = id` 且 `status = 2`（在售）的条数。
  - `schoolName` / `campusName` 走 `DictionaryCache`；字典缺失时为 null。
  - 查看者身份：`StpUtil.isLogin() ? loginId : null`，异常也按匿名处理。
  - `self = (id == 当前用户 id)`；`blocked = !self && 登录 && 我拉黑了他`；`blockedByPeer = !self && 登录 && 他拉黑了我`。匿名访问时这两个字段为 `false`。
- **可能错误码**：`10001` PARAM_ERROR（用户不存在）、`90001` SYSTEM_ERROR

### 7. 拉黑用户（拉黑后双方不可私聊）
- **方法与路径**：`POST /api/v1/users/{id}/block`
- **鉴权**：需要登录
- **请求参数**（path/query）：
  | 位置 | 参数 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- | --- |
  | path | `id` | Long | 是 | 被拉黑的用户 id |
- **请求体**：无
- **响应示例**：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": null,
    "traceId": "3f2a9c1d8e7b6a54"
  }
  ```
- **业务规则 / 校验**：
  - 目标为 `null` → `10001 "用户不存在"`；与自己相同 → `60004`（`ADMIN_SELF_OPERATION`，文案「不能拉黑自己」）。
  - 插入 `user_block(user_id = 当前用户, blocked_user_id = 目标)`，`created_at` 由 DB 默认值写入。
  - **幂等**：命中唯一索引 `uk_block_pair` 抛 `DuplicateKeyException` 时被吞掉，重复拉黑仍返回成功。
  - **不校验目标用户是否真实存在**（只防 null 和自己）。
  - 拉黑是**单向存储、双向生效**：私聊侧用 `UserBlockService.blockedEither` 判定「任一方向存在拉黑即禁止会话/发消息」。
  - 不写入任何通知或计数。
- **可能错误码**：`10001` PARAM_ERROR、`10002` NOT_LOGIN、`60004` ADMIN_SELF_OPERATION（不能拉黑自己）、`90001` SYSTEM_ERROR

### 8. 解除拉黑
- **方法与路径**：`DELETE /api/v1/users/{id}/block`
- **鉴权**：需要登录
- **请求参数**（path/query）：
  | 位置 | 参数 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- | --- |
  | path | `id` | Long | 是 | 被解除拉黑的用户 id |
- **请求体**：无
- **响应示例**：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": null,
    "traceId": "3f2a9c1d8e7b6a54"
  }
  ```
- **业务规则 / 校验**：
  - 只删**自己发起**的那条：`DELETE FROM user_block WHERE user_id = 当前用户 AND blocked_user_id = id`。
  - **幂等**：删 0 行也返回成功（不报「未拉黑」错误）。
  - 对方拉黑我的记录不会被动到：双向拉黑时解除只是单方面解除，仍需 `blockedByPeer` 提示用户。
  - 无入参业务校验（id 为空会由路径匹配失败处理，本方法不做 null 判断）。
- **可能错误码**：`10002` NOT_LOGIN、`90001` SYSTEM_ERROR

### 9. 我拉黑的用户（带昵称/头像，可直接渲染列表）
- **方法与路径**：`GET /api/v1/users/blocks`
- **鉴权**：需要登录
- **请求参数**（path/query）：无（**不分页、无筛选**，一次返回全部）
- **请求体**：无
- **响应示例**：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": [
      {
        "id": 31,
        "blockedUserId": 15,
        "nickname": "隔壁宿舍的",
        "avatar": "/static/avatar/default.png",
        "creditScore": 90,
        "identityFlag": 0,
        "shopName": "手工零食铺",
        "schoolName": "示例大学",
        "campusName": "东校区",
        "createdAt": "2026-10-29T20:15:00",
        "blockedByPeer": true
      }
    ],
    "traceId": "3f2a9c1d8e7b6a54"
  }
  ```
- **业务规则 / 校验**：
  - 查 `user_block WHERE user_id = 当前用户 ORDER BY id DESC`；无记录直接返回空数组 `[]`。
  - 批量 `selectBatchIds` 取被拉黑用户，补齐 `nickname/avatar/creditScore/identityFlag/shopName`；学校/校区名走字典缓存。
  - `blockedByPeer` 由一次「谁拉黑了我」的查询（`blocked_user_id = 当前用户`）聚合后判定，避免循环内逐条查库。
  - **不含手机号等任何联系方式**（黑名单页没有理由比公开主页看到更多）。
  - 被拉黑用户若已从 `sys_user` 删除：只返回 `id/blockedUserId/createdAt/blockedByPeer`，展示字段为 null（JSON 中被省略）。
- **可能错误码**：`10002` NOT_LOGIN、`90001` SYSTEM_ERROR

## SchoolController（`/api/v1/schools`）

> 整个 `/api/v1/schools/**` 在 Sa-Token 白名单内，两个接口都公开。注意这两个接口**直接返回实体**（不是 VO），且**不经 `DictionaryCache` 的列表缓存**。

### 10. 学校列表（公开）
- **方法与路径**：`GET /api/v1/schools`
- **鉴权**：公开
- **请求参数**（path/query）：无
- **请求体**：无
- **响应示例**：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": [
      {
        "id": 1,
        "name": "示例大学",
        "city": "杭州",
        "source": 1,
        "status": 1,
        "createdAt": "2026-01-01T00:00:00",
        "updatedAt": "2026-01-01T00:00:00"
      },
      {
        "id": 2,
        "name": "第二大学",
        "city": "南京",
        "source": 2,
        "status": 1,
        "createdAt": "2026-02-01T00:00:00",
        "updatedAt": "2026-02-01T00:00:00"
      }
    ],
    "traceId": "3f2a9c1d8e7b6a54"
  }
  ```
- **业务规则 / 校验**：
  - `SELECT ... FROM school WHERE status = 1`（只返回启用学校，停用不出现）。
  - **无排序条件**（按 MySQL 默认返回顺序，前端如需要请自行按 `id`/`name` 排序）。
  - 无分页、无关键字搜索、无城市筛选。
  - 返回实体 `School` 全字段：`id`、`name`、`city`、`source`（1 平台开通 2 用户申请）、`status`、`createdAt`、`updatedAt`。
- **可能错误码**：`90001` SYSTEM_ERROR

### 11. 校区列表（公开）
- **方法与路径**：`GET /api/v1/schools/{schoolId}/campuses`
- **鉴权**：公开
- **请求参数**（path/query）：
  | 位置 | 参数 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- | --- |
  | path | `schoolId` | Long | 是 | 学校 id |
- **请求体**：无
- **响应示例**：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": [
      {
        "id": 1,
        "schoolId": 1,
        "name": "东校区",
        "mapType": 1,
        "mapConfig": "{\"imgUrl\":\"/static/map/campus-1.png\",\"width\":2000,\"height\":1500}",
        "status": 1,
        "createdAt": "2026-01-01T00:00:00"
      }
    ],
    "traceId": "3f2a9c1d8e7b6a54"
  }
  ```
- **业务规则 / 校验**：
  - `SELECT ... FROM campus WHERE school_id = {schoolId} AND status = 1`，只返回启用校区。
  - **不校验学校是否存在**：`schoolId` 不存在或学校已停用时返回空数组，不报错。
  - 无排序条件（DB 默认顺序）。
  - 返回实体 `Campus` 全字段，其中 `mapType` 1=自绘平面图 / 2=第三方地图，`mapConfig` 是 **JSON 字符串**（实体字段类型为 `String`，前端需自行 `JSON.parse`；内容形如 `{imgUrl,width,height,minZoom,maxZoom,center,polygon}`）。
- **可能错误码**：`90001` SYSTEM_ERROR

### 实现顺序建议

1. `SysUser` / `UserBlock` / `School` / `Campus` 实体 + 四个 Mapper（先能跑通 `selectById`）。
