# 08 · 单体接口：平台严选（代卖 / 优惠券 / 秒杀）

> 代码位置：`ershou-server`（Spring Boot 3.3.5 / MyBatis-Plus 3.5.9 / Sa-Token 1.39.0 / JDK21）。
> 模块包：`com.ershou.campus.module.platform`。
> 基础路径：**`/api/v1/platform/shop`**（公开读）、**`/api/v1/platform/me`**（登录用户动作）、**`/api/v1/platform/admin`**（运营后台，由 `PlatformAdminController` 与 `PlatformConsoleController` 两个类共用同一类级路径）。
> 涉及表：`item`（平台列 `seller_type` / `platform_point_id`）、`platform_consign_point`、`platform_coupon`、`platform_coupon_user`、`platform_flash_sale`、`platform_flash_sale_item`、`platform_seckill_record` —— 共 7 张（其中纯 `platform_*` 前缀为 6 张，`item` 是既有商品表新增平台列）。
> 本文所有接口、字段、错误码均来自当前源码（控制器 / 服务 / Mapper / 迁移脚本 `sql/migration-platform.sql`）；源码未体现之处标注“以源码为准”。

## 1. 模块概览

| 项 | 说明 |
| --- | --- |
| 公开读 | `/api/v1/platform/shop/**`，在 `SaTokenConfig` 白名单内，**游客可访问**；券/秒杀的 `claimed` / `grabbed` 字段在有登录态时按当前用户计算，未登录恒 `false`（`PlatformShopController#currentUserIdOrNull` 用 `StpUtil.isLogin()` 判断，不抛未登录异常） |
| 登录用户动作 | `/api/v1/platform/me/**`，**不在白名单**，由 `SaInterceptor` 统一 `StpUtil.checkLogin()`；抢券/抢购的失败（抢完、超限、限流等）仍返回 HTTP 200 + 业务子码 |
| 运营后台 | `/api/v1/platform/admin/**`，Sa-Token 只保证“已登录”，**每个接口第一行调用 `AdminAuthService#requireAdminId()`** 再校验运营身份，未通过抛 `NO_PERMISSION`（10003，message “需要运营人员权限”） |
| 登录凭证 | 请求头 `Authorization: Bearer <token>`（Sa-Token 默认读取方式） |
| 返回结构 | `Result<T> = {code, message, data, traceId}`，成功 `code=0`、`message="ok"`；分页 `data=PageResult<T>={total,pageNum,pageSize,records}` |
| 业务子码 | 抢券 / 抢购在 `data` 内另有 `code`：`1` 成功 / `0` 抢完 / `-1` 未预热 / `-2` 超限 / `-3` 未开始或已结束 / `-4` 限流（`PlatformCacheService` 常量），**不是** `Result.code` |
| 序列化 | `spring.jackson.default-property-inclusion=non_null`：**值为 null 的字段不会出现在 JSON 中**（例如无秒杀场次时 `GET /shop/flash-sale` 的 `data` 字段整体缺省）；时间格式 `yyyy-MM-dd HH:mm:ss`，时区 `Asia/Shanghai` |
| 默认校区 | shop 接口的 `campusId` 默认 `2`（`@RequestParam(defaultValue = "2")`）；运营台券/秒杀/概览的 `campusId` 缺省时服务层按 `2` 处理（`DEFAULT_CAMPUS_ID = 2L`） |
| 平台官方卖家 | `PlatformProperties#sellerId`，默认 `1000`（`ershou.platform.seller-id`）；平台商品 `seller_type=2`，`seller_id=1000` |
| 商品有效期 | `ershou.platform.item-valid-days`，默认 `30` 天；重新上架时按当前时间 + 该天数 |
| 缓存 | 业务缓存 key 前缀 `ershou:platform:`（`PlatformCacheKeys`）；点位列表 TTL 540s、概览/券列表 TTL 54s、当前场次 TTL 27s（均为“设计 60s/30s/10min”扣掉 `JsonCache` 的 +0~10% 抖动余量），写路径主动失效；库存 key TTL 到 `end_at + 1h` |
| 依赖的其它模块 | `OrderService#platformBuy`（建平台面交单）、`PlatformTradeMapper#decrementPlatformStock`（条件扣库存）、`ItemIndexService#syncById`（ES 同步）、`CacheEvictor#itemChanged`、`CampusMapper`、`ItemCategoryMapper`、`AdminAuthService` |

### 1.1 统一错误处理

- `BizException` 由 `GlobalExceptionHandler` 转成 `Result.fail(code, message)`，**HTTP 状态码仍为 200**。
- 未登录（`NotLoginException`）→ `10002`。
- `@Valid` 校验失败（`MethodArgumentNotValidException` / `BindException`）→ `10001`，message 取字段注解提示。
- 未捕获异常 → `90001`。
- 平台模块自身只抛 `PARAM_ERROR(10001)`、`NO_PERMISSION(10003)`、`ITEM_NOT_FOUND(30001)`、`ITEM_LOCKED(30004)`、`ITEM_STATUS_ERROR(30006)`，抢券/抢购的细粒度原因走 `data.code` 子码而不是异常。

### 1.2 平台模块会出现的 `ResultCode`

| 枚举 | code | 默认 message | 主要触发点 |
| --- | --- | --- | --- |
| `SUCCESS` | 0 | ok | 所有成功响应 |
| `PARAM_ERROR` | 10001 | 参数校验失败 | Bean Validation；代卖点/券/场次/分类不存在或参数非法；时间格式错误 |
| `NOT_LOGIN` | 10002 | 未登录或登录已过期 | `/platform/me/**`、`/platform/admin/**` 未带 token |
| `NO_PERMISSION` | 10003 | 无权限访问 | `requireAdminId()` 判定非运营（实际 message 被覆盖为“需要运营人员权限”） |
| `ITEM_NOT_FOUND` | 30001 | 商品不存在或已删除 | 平台商品不存在（直购/后台编辑/上下架） |
| `ITEM_LOCKED` | 30004 | 商品刚被他人锁定，看看同款？ | 直购预检库存不足（message 覆盖为“库存不足（剩余 N 件）”）；`OrderService` 条件扣库存 0 行 |
| `ITEM_STATUS_ERROR` | 30006 | 当前商品状态不允许该操作 | 直购时平台商品非 `status=2` |
| `SYSTEM_ERROR` | 90001 | 系统开小差了，请稍后再试 | 未捕获异常 |

## 2. 数据模型简表

DDL 见 `sql/migration-platform.sql`。下文只列平台模块实际读写的列。

### 2.1 `item`（既有商品表，平台列）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `seller_id` | BIGINT | 平台商品固定为平台账号（默认 1000） |
| `seller_type` | TINYINT NOT NULL DEFAULT 1 | **1=个人卖家，2=平台自营（官方代卖）**；平台模块所有 SQL 只碰 `seller_type=2` |
| `platform_point_id` | BIGINT NULL | 指向 `platform_consign_point.id`，**不是** `trade_point.id`；个人商品为 NULL |
| `stock` / `is_unique` | INT / TINYINT | 平台多库存商品 `is_unique=0`；发布时 `stock<=1 → 1`，编辑库存时 `stock>1 → 0` |
| `status` | TINYINT | `0 草稿 / 1 审核中 / 2 在售 / 3 已锁定 / 4 已售出 / 5 已下架 / 6 审核未通过 / 7 已过期 / 8 违规下架`；平台商品免审核直接 `2`，运营台下架置 `5` |
| `audit_result` | TINYINT | 平台发布时固定写 `1`（免审核） |
| `expire_at` / `published_at` | DATETIME | 发布时 `expire_at = now + itemValidDays`；重新上架时重算 |
| `prefer_point_id` | BIGINT | 平台发布时**强制写 NULL**（指向 `trade_point` 另一套 id 空间，写错会显示错误地名） |
| `trade_mode` | TINYINT | 平台发布固定 `1` |
| `view_count` | INT | 运营台列表展示 |

索引：`idx_item_platform (seller_type, status, campus_id)`。

### 2.2 `platform_consign_point`（代卖 / 自提点）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT PK AUTO | 自提点 id；订单 `point_id` 存的就是它 |
| `campus_id` | BIGINT NOT NULL | 所属校区；新建必填 |
| `name` / `address` | VARCHAR(64) / VARCHAR(255) | 名称、详细地址；均必填 |
| `lng` / `lat` | DECIMAL(10,7) NULL | GCJ-02 坐标；可都为空（纯地址展示），**不可只填一个** |

| `sort` | INT DEFAULT 0 | 小的靠前；公开列表按 `sort, id` 升序 |
| `status` | TINYINT DEFAULT 1 | **1=启用，0=停用；删除是软删（置 0）**，不破坏历史商品引用 |

索引：`idx_ppoint_campus (campus_id, status, sort)`。

### 2.3 `platform_coupon`（券模板）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `campus_id` | BIGINT NOT NULL | 所属校区 |
| `name` | VARCHAR(64) | 券名称 |
| `type` | TINYINT | **1=满减，2=折扣** |
| `threshold_amount` | DECIMAL(10,2) NULL | 满减门槛（type=1，必须 `>=0`） |
| `discount_amount` | DECIMAL(10,2) NULL | 减免金额（type=1，必须 `>0`） |
| `discount_rate` | DECIMAL(4,2) NULL | 折扣率（type=2），`0.90 = 9 折`；入库前归一到 `(0,1)` 并保留 2 位 |
| `total_stock` | INT NOT NULL | 总库存，至少 1 |
| `per_user_limit` | INT DEFAULT 1 | 每人限领张数，至少 1 |
| `start_at` / `end_at` | DATETIME NOT NULL | 生效时间窗；`start_at` 必须早于 `end_at` |
| `status` | TINYINT DEFAULT 1 | 1=启用，0=停用 |

索引：`idx_pcoupon_campus (campus_id, status, start_at, end_at)`。

### 2.4 `platform_coupon_user`（用户已领券）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `coupon_id` / `user_id` | BIGINT NOT NULL | **唯一键 `uk_pcoupon_user (coupon_id, user_id)`**：每人每券只有一条记录，是“防重复领取”的 DB 权威判据 |
| `status` | TINYINT DEFAULT 1 | **1=未用，2=已用，3=过期**；本轮只领不用，恒为 1 |
| `received_at` | DATETIME | 领取时间；“我的券”按它倒序 |
| `used_at` / `order_id` | DATETIME / BIGINT NULL | 预留（本轮未接入下单抵扣） |

### 2.5 `platform_flash_sale`（秒杀场次）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `campus_id` | BIGINT NOT NULL | 所属校区 |
| `title` | VARCHAR(80) | 场次标题 |
| `start_at` / `end_at` | DATETIME | 时间窗；`start_at` 必须早于 `end_at` |
| `status` | TINYINT DEFAULT 1 | **1=预告，2=进行中，3=已结束** |
| `sort` | INT DEFAULT 0 | 同校区多个进行中场次时按 `sort ASC, id DESC` 取第一个（`selectCurrent`） |

“当前场次”判定（`PlatformFlashSaleMapper#selectCurrent`）：`status=2 AND start_at <= NOW() AND end_at > NOW()`，同校区按 `sort ASC, id DESC LIMIT 1`。

### 2.6 `platform_flash_sale_item`（场次商品）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `flash_sale_id` / `item_id` | BIGINT | **唯一键 `uk_pflash_item (flash_sale_id, item_id)`**：同一场次内商品不重复 |
| `seckill_price` | DECIMAL(10,2) | 秒杀价，`>0` |
| `seckill_stock` | INT | 秒杀总库存，至少 1；加商品时会保证 `item.stock >= seckill_stock` |
| `sold_count` | INT DEFAULT 0 | **仅展示口径**；库存真值在 Redis，预热时按 `seckill_stock - COUNT(platform_seckill_record)` 重算 |
| `per_user_limit` | INT DEFAULT 1 | 每人限购；DB 唯一键使“每人实际只能抢到 1 次” |
| `sort` | INT DEFAULT 0 | 场次内排序，列表按 `sort, id` 升序 |

### 2.7 `platform_seckill_record`（抢购成功记录）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `item_id` / `user_id` | BIGINT NOT NULL | **唯一键 `uk_pseckill_item_user (item_id, user_id)`**：同一用户同一商品只能有一条成功记录 |
| `order_id` | BIGINT NULL | 生成的面交单 id |
| `price` | DECIMAL(10,2) NULL | 成交价（秒杀价） |
| `created_at` | DATETIME | 抢购时间；预热按此重算 Redis 库存与已购 Hash |

## 3. 接口清单

> 说明：`admin` 与 `console` 两个 Controller 类级路径都是 `/api/v1/platform/admin`，靠 **method + path** 区分，无冲突。
> 模板中的“响应示例”按 `non_null` 序列化习惯省略了 null 字段；`traceId` 为 MDC 中的链路 id，示例中省略。

### 3.1 `PlatformShopController`（公开读，5 个）

#### 1. 平台专区概览
- **方法与路径**：`GET /api/v1/platform/shop/overview`
- **鉴权**：公开
- **请求参数**：

  | 位置 | 参数 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- | --- |
  | query | `campusId` | Long | 否 | 默认 `2`；用于统计该校区数据并作为缓存 key 的一部分（null 时 key 用 `0`） |

- **请求体**（如有）：无
- **响应示例**：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": {
      "platformItemCount": 4,
      "pointCount": 3,
      "couponCount": 3,
      "flashSaleId": 1,
      "flashSaleTitle": "官方严选 · 限时秒杀",
      "flashSaleStatus": 2
    }
  }
  ```
- **业务规则 / 校验**：
  - `platformItemCount`：`item.seller_type=2 AND status=2 AND campus_id=?` 的数量。
  - `pointCount`：`platform_consign_point.campus_id=? AND status=1` 的数量。
  - `couponCount`：“启用 + 在时间窗内 + 还有剩余库存”的券数；“剩余库存”优先读 Redis，Redis 未预热（返回 -1）时按 `total_stock > 0` 判断。
  - 秒杀字段取该校区“当前场次”（`status=2` 且在时间窗内）；无场次时三个字段均为 null（JSON 中缺省）。
  - 聚合结果缓存 54s（key `ershou:platform:overview:{campusId}`）。
- **可能错误码**：`90001`（未捕获异常；Redis 读取本身在服务内兜底）。

#### 3. 平台商品分页
- **方法与路径**：`GET /api/v1/platform/shop/items`
- **鉴权**：公开
- **请求参数**：

  | 位置 | 参数 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- | --- |
  | query | `campusId` | Long | 否 | 默认 `2` |
  | query | `pointId` | Long | 否 | 平台代卖点 id（`item.platform_point_id`） |

  | query | `sort` | String | 否 | 默认 `latest`；只认 `latest` / `price_asc` / `price_desc`，其它值按 `latest` 处理 |
  | query | `pageNum` | long | 否 | 默认 `1`；小于 1 按 1 |
  | query | `pageSize` | long | 否 | 默认 `12`；范围 1~100（超过按 100） |

- **请求体**（如有）：无
- **响应示例**：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": {
      "total": 4,
      "pageNum": 1,
      "pageSize": 12,
      "records": [
        {
          "id": 101,
          "title": "[官方严选] 九成新显示器",
          "description": "官方质检，校内自提",
          "price": 425.00,
          "originalPrice": 500.00,
          "coverUrl": "https://cdn.example.com/i.jpg",
          "images": ["https://cdn.example.com/i.jpg"],
          "categoryId": 3,
          "categoryName": "数码",
          "conditionLevel": 3,
          "stock": 5,
          "status": 2,
          "statusText": "在售",
          "publishedAt": "2026-10-01 10:00:00",
          "pointId": 1,
          "pointName": "一号门 · 官方代卖点",
          "sellerType": 2,
          "seckillPrice": 255.00,
          "seckillStock": 4
        }
      ]
    }
  }
  ```
- **业务规则 / 校验**：
  - 只返回 `seller_type=2 AND status=2`；排序：`latest` → `published_at DESC, id DESC`；`price_asc` → `price ASC, id DESC`；`price_desc` → `price DESC, id DESC`。
  - `images` 由 `item.images`（JSON 字符串）解析成数组；解析失败返回空数组。
  - `sellerType` 固定为 2。
  - 若该校区存在“当前场次”，对场次内商品叠加 `seckillPrice` 与 `seckillStock`；`seckillStock` 优先读 Redis，未预热时回退 `seckill_stock - sold_count`（不小于 0）。叠加失败只记日志，不影响列表。
  - `pageNum/pageSize` 响应回显的是**夹取后**的值。
- **可能错误码**：`90001`。

#### 4. 可领优惠券列表
- **方法与路径**：`GET /api/v1/platform/shop/coupons`
- **鉴权**：公开（有登录态时 `claimed` 按当前用户算）
- **请求参数**：

  | 位置 | 参数 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- | --- |
  | query | `campusId` | Long | 否 | 默认 `2` |

- **请求体**（如有）：无
- **响应示例**：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": [
      {
        "id": 1,
        "name": "满 50 减 8",
        "type": 1,
        "thresholdAmount": 50.00,
        "discountAmount": 8.00,
        "perUserLimit": 1,
        "startAt": "2026-10-29 00:00:00",
        "endAt": "2026-11-06 00:00:00",
        "status": 1,
        "totalStock": 100,
        "leftStock": 99,
        "claimed": true,
        "claimable": false
      }
    ]
  }
  ```
- **业务规则 / 校验**：
  - 只返回 `status=1` 且 `start_at <= now <= end_at` 的券模板，按 `id ASC`；模板列表缓存 54s。
  - `leftStock` 实时读 Redis（`ershou:platform:coupon:stock:{id}`）；Redis 未预热/异常返回 -1 时回退 DB 口径 `total_stock - COUNT(platform_coupon_user)`，保证不展示 -1。
  - `claimed`：已登录时按 `(coupon_id,user_id)` 查 DB；游客恒 false。
  - `claimable = 券启用且在时间窗内 && leftStock > 0 && !claimed`。
  - 返回的是缓存对象，`leftStock/claimed/claimable` 每次请求实时覆盖。
- **可能错误码**：`90001`。

#### 5. 当前进行中的秒杀场次
- **方法与路径**：`GET /api/v1/platform/shop/flash-sale`

- **请求参数**：

  ```json

    "data": {

  ```
  失败示例（HTTP 仍 200，`Result.code` 仍为 0，看 `data.code`）：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": {
      "success": false,
      "code": -2,
      "message": "该券每人限领 1 张",

    }
  }
  ```
- **业务规则 / 校验**：
  - 执行顺序（重要）：
    1. 券不存在或 `status=0` → 抛 `PARAM_ERROR`（10001，“优惠券不存在或已停用”）。
    2. **已领过**（DB `(coupon_id,user_id)` 存在）→ 直接返回子码 `-2`，且**不消耗限流次数**。
    3. 限流：Redis `INCR + EXPIRE 5s`，5 秒内只放行 1 次，超限返回 `-4`（Redis 故障时放行）。
    4. 时间窗外 → `-3`（不碰 Lua）。
    5. Lua 原子扣减库存与限领 Hash：`stock key 不存在 → -1`（未预热）；`stock<=0 → 0`（领完）；`HGET(user) >= perUserLimit → -2`；成功则 `DECR` + `HINCRBY(user,1)` → 1。
    6. DB 落 `platform_coupon_user`（`status=1`，`received_at=now`）；唯一键冲突 → 回滚 Redis（`INCR` 库存、`HINCRBY -1`）并返回 `-2`；其它运行时异常同样回滚 Redis 后抛出（`90001`）。
  - **每人限领的实际效果**：DB 唯一键 `(coupon_id,user_id)` 决定“每人每券最多一条领取记录”，即使 `per_user_limit > 1`，第二次领取也会被 DB 兜底拒绝并按 `-2` 返回；`per_user_limit` 同时是 Redis 快路径的限领阈值。
  - 成功响应里的 `leftStock` 优先读 Redis，未命中回退 DB 口径；失败时也返回当前剩余，便于前端刷新按钮。
  - 本轮券**不参与下单抵扣**，领取后状态恒为 1（未用）。
- **可能错误码**：`10001`（券不存在/停用、缺少券或用户）、`10002`（未登录）、`90001`（落库异常）；业务子码 `0/-1/-2/-3/-4` 在 `data.code`。

## 4. 平台严选 / 代卖 / 优惠券 / 秒杀完整业务流程

### 4.1 商品侧：发布 → 展示 → 直购

1. **运营建点位**：`POST /platform/admin/points` 建代卖/自提点（`campus_id` + `status=1`）。点位是“官方自提货架”的所在地，与 `trade_point`（校内地图面交点）是两套数据，`item.platform_point_id` 只指向本表。
2. **运营发布平台商品**：`POST /platform/admin/items`，后端强制 `seller_id=平台账号(1000)`、`seller_type=2`、`status=2`（免审核）、`audit_result=1`、`prefer_point_id=null`、`expire_at=now+30天`；写库后同步 ES、清商品缓存与概览缓存。
3. **用户浏览**（游客可）：`GET /platform/shop/overview`、`/points`、`/items`（只 `seller_type=2 AND status=2`，可按点位/分类筛选、按最新/价格排序）。若当前有秒杀场次，列表卡片会叠加 `seckillPrice/seckillStock`。
4. **直购**：`POST /platform/me/items/{id}/buy`。
   - 预检：平台商品存在、`status=2`、`stock >= quantity`。
   - `OrderService#platformBuy` 用 **条件更新扣库存**（`WHERE seller_type=2 AND status=2 AND stock>=?`，不锁库、不写 `status=3`）；扣减后 `stock=0` 则商品置 `status=4`。
   - 生成面交单：卖家=平台账号、买家=当前用户、`status=2`（待自提）、`seller_confirm_at=now`、`point_id=平台点 id`，无“卖家确认”环节。
5. **履约**：订单状态机、完成/取消后的库存回收属 order 模块（`PlatformTradeMapper#settlePlatformItem` / `restorePlatformStock`），本模块只提供下单入口。
6. **运营管理**：`GET /platform/admin/items`（全状态分页）、`PUT /platform/admin/items/{id}`（只改标题/价格/库存/代卖点）、`POST .../offline`（`status=5`）、`POST .../online`（`status=2` + 有效期重算）；每次写操作都同步 ES + 清缓存。
7. **运营看数**：`GET /platform/admin/overview`（商品/点位/券/秒杀/订单/GMV/库存告警），`GET /platform/admin/orders`（只含平台账号作为卖家的订单）。

### 4.2 优惠券：配置 → 预热 → 领取 → 我的券

1. **配置**：`POST/PUT /platform/admin/coupons`。
   - `type=1` 满减：门槛 `>=0`、减免 `>0`；`type=2` 折扣：`discountRate` 支持 `0.9 / 9 / 90 / 85`，统一归一为 `(0,1)` 的 2 位小数。
   - 时间窗必须 `start_at < end_at`；总库存 `>=1`；编辑时若“已发放数 > 新总库存”直接拒绝。
2. **预热/重建**：
   - 启动时 `PlatformCacheWarmup`（`ApplicationRunner`）调 `warmup(false)`：只补缺失 key，不覆盖进行中的抢购状态；多实例用 `SET NX EX 30` 锁。
   - 口径：`stock = max(total_stock - COUNT(platform_coupon_user), 0)`；`users` Hash 按 DB 领取记录整体回填（field=userId，value=已领次数）；TTL 到 `end_at + 1h`。
   - 单券写操作后 `rebuildCoupon(id)` 只重建这一张券；后台 `POST /cache/refresh` 做强制全量重建。
3. **领券链路**（`POST /platform/me/coupons/{id}/claim`）：
   - DB 判重（已领 → `-2`，不消耗限流）→ 5s 限流（`-4`）→ 时间窗（`-3`）→ Lua 原子扣减（`-1` 未预热 / `0` 领完 / `-2` 超限 / 1 成功）→ 落 `platform_coupon_user`。
   - 落库失败（唯一键/运行时异常）**必须补偿 Redis**（库存 `INCR`、用户 Hash `HINCRBY -1`），否则会出现“没领到但库存少一张”。
   - 唯一键 `(coupon_id,user_id)` 是最终权威：实际效果是每人每券最多领 1 条记录。
4. **展示**：`GET /platform/shop/coupons` 每次实时覆盖 `leftStock`（Redis 优先、DB 兜底）与 `claimed/claimable`。
5. **我的券**：`GET /platform/me/coupons` 以 DB 为准，含券模板信息与领取状态。
6. **本轮边界**：券不参与下单抵扣（`couponId` 只记日志），`platform_coupon_user.status` 恒为 1，`used_at/order_id` 预留。

### 4.3 秒杀：建场 → 加品 → 预热 → 抢购

1. **建场**：`POST /platform/admin/flash-sales`，默认 `status=1`（预告）、`sort=0`；后续用 `PUT` 改时间/状态/排序，或用 `POST .../status` 切 1/2/3。
2. **加品**：`POST /platform/admin/flash-sales/{id}/items`。
   - 必须是平台商品（`seller_type=2`）；同场次不重复；`seckill_stock>=1`。
   - 若 `item.stock < seckill_stock`，自动抬高 `item.stock` 并同步 `is_unique`（否则第 1 单后商品归零，多份秒杀退化）。
   - 每加/移除一次都会失效场次缓存并只重建该场次的库存 key；移除时还会删掉该商品的库存/已购 key。
3. **预热**：`warmupSeckills` 只处理 `status=2 AND end_at > now` 的场次；每个商品 `stock = max(seckill_stock - COUNT(platform_seckill_record), 0)`，已购 Hash 按记录回填；TTL 到 `end_at+1h`。
4. **展示**：`GET /platform/shop/flash-sale` 返回当前场次（`status=2` 且在时间窗内）；`remainSeconds`、`status`（预告/进行中）、每件 `leftStock`、`grabbed` 都是读缓存后实时重算。
5. **抢购链路**（`POST /platform/me/flash-sale/{itemId}/grab`）：
   - 必须命中当前场次的秒杀商品（否则 `-3`）→ DB 判重（已抢 → `-2`，不消耗限流）→ 商品 `status=2 && stock>=1`（否则 `0`）→ 5s 限流（`-4`）→ Lua 原子扣减。
   - Lua 成功后调 `OrderService#platformBuy` 建平台单（数量固定 1、成交价=秒杀价、自提点=商品平台点）；**建单失败必须回滚 Redis**，避免“没抢到还占名额”。
   - 订单生成后写 `platform_seckill_record` + `sold_count+1`（`sold_count < seckill_stock` 才加）；唯一键冲突不回滚已生成订单，只记日志。
   - 唯一键 `(item_id,user_id)` 决定每人每商品只能成功 1 次。
6. **运营视角**：`GET /platform/admin/flash-sales` 返回场次 + 商品明细 + 实时剩余；`GET /platform/admin/overview` 汇总场次库存/销量/剩余小时数。

### 4.4 Redis key 与缓存一致性

| key | 类型 | 用途 / TTL |
| --- | --- | --- |
| `ershou:platform:points:{campusId}` | String(JSON) | 公开点位列表，540s |
| `ershou:platform:coupons:{campusId}` | String(JSON) | 券模板列表，54s |
| `ershou:platform:overview:{campusId}` | String(JSON) | 专区概览，54s |
| `ershou:platform:flash:{campusId}` | String(JSON) | 当前场次，27s |
| `ershou:platform:coupon:stock:{couponId}` | String(int) | 券剩余库存，end_at+1h |
| `ershou:platform:coupon:users:{couponId}` | Hash | userId → 已领张数，end_at+1h |
| `ershou:platform:seckill:stock:{itemId}` | String(int) | 秒杀剩余库存，end_at+1h |
| `ershou:platform:seckill:users:{itemId}` | Hash | userId → 已购件数，end_at+1h |
| `ershou:platform:rate:claim:{userId}` | String | 抢券限流，INCR+EXPIRE 5s，>1 拒绝 |
| `ershou:platform:rate:grab:{userId}` | String | 抢购限流，同上 |
| `ershou:platform:lock:warmup` | String | 预热分布式锁，SET NX EX 30 |

一致性策略：
- **DB 是领取/成交真值，Redis 是并发闸门**：key 丢失/过期/重建只影响抢的瞬间，预热永远按 DB 重算。
- 写路径主动失效：点位增删改删 points+overview；商品发布/上下架/编辑删 overview（并清商品缓存）；券增改/启停删 coupons+overview 并重建单券；场次写删 flash+overview 并重建单场次；移除秒杀商品额外删库存/用户 key。
- 公开读接口都对“Redis 未预热（返回 -1）”做了 DB 回退，页面不会展示 -1 或负数。
