## 一、微服务概览

| 组件 | 服务名（Nacos `spring.application.name`） | 端口 | 职责 |
| --- | --- | --- | --- |
| 网关 | `ershou-gateway` | **8088** | 统一入口、Sa-Token 鉴权、身份透传、路由/反代、Sentinel 限流、CORS |
| user-service | `ershou-user-service` | **8081** | 短信验证码、登录/登出、当前用户、学校/校区 |
| item-service | `ershou-item-service` | **8082** | 商品列表/详情、分类、内部商品快照与库存锁定、MQ 销量累加 |
| order-service | `ershou-order-service` | **8083** | 面交单创建（Seata 全局事务）、我的面交单、内部订单查询、MQ 生产 |
| 旧单体（未迁移路径） | — | **8080** | 网关回退反代目标（`ershou.gateway.legacy-uri`） |

**配置来源（Nacos）**

各服务本地 `application.yml` 只保留端口、服务名、Nacos 地址与 `spring.config.import`，其余全部来自 Nacos（`group=DEFAULT_GROUP`，`file-extension=yaml`）：

| 服务 | Nacos dataId | 主要配置项 |
| --- | --- | --- |
| gateway | `ershou-gateway.yaml` | Redis db0、Sa-Token、Sentinel、`ershou.gateway.legacy-uri/ws-uri/item-qps`、Gateway HTTP 超时 |
| user-service | `ershou-user-service.yaml` | MySQL `ershou_user`、Redis db1、Sa-Token、`ershou.sms.*`、`ershou.admin.role-flag`、`ershou.cloud.session-redis-database=0` |
| item-service | `ershou-item-service.yaml` | MySQL `ershou_item`、Redis db2、RabbitMQ、Seata AT、`ershou.item.detail-cache-seconds/page-max` |
| order-service | `ershou-order-service.yaml` | MySQL `ershou_order`、Redis db3、RabbitMQ、Seata TM、`feign.sentinel.enabled`、Feign 超时、`ershou.order.max-qty/default-status` |

> Nacos 地址默认 `127.0.0.1:8848`，可用环境变量 `NACOS_ADDR` 覆盖。网关地址参数可在 Nacos 中改，改 `legacy-uri` 即可把未迁移路径反代到别的机器。

## 二、统一约定

### 2.1 返回结构

所有接口返回 `Result<T>`（[`Result.java`](../ershou-cloud/ershou-cloud-common/src/main/java/com/ershou/cloud/common/result/Result.java)）：

```json
{
  "code": 0,
  "message": "ok",
  "data": { },
  "traceId": "a1b2c3d4e5f60708"
}
```

- 成功 `code=0`、`message="ok"`；业务错误以非 0 `code` 表示，HTTP 状态通常仍是 200。
- `traceId` 来自 MDC，由 `TraceIdFilter` 写入（优先沿用网关的 `X-Trace-Id`，没有则生成 16 位）。
- 无返回值接口 `data=null`。

分页接口的 `data` 是 `PageResult<T>`（[`PageResult.java`](../ershou-cloud/ershou-cloud-common/src/main/java/com/ershou/cloud/common/result/PageResult.java)）：

```json
{
  "total": 12,
  "pageNum": 1,
  "pageSize": 10,
  "records": []
}
```

> 微服务未配置 Jackson 的 `non_null` 排除策略，`data=null`、VO 中的 null 字段会原样序列化输出；以实际序列化为准。

### 2.2 鉴权约定

1. 所有**经网关 8088** 的请求由 Sa-Token 统一鉴权：Header `Authorization: Bearer <token>`。
2. 网关 `SaReactorFilter` 在 **WebFilter 阶段** 判断：公开路径直接放行；非公开且未登录时返回 **HTTP 401**：
   ```json
   {"code":10002,"message":"未登录或登录已过期","data":null,"traceId":"..."}
   ```
3. 已登录时把 `StpUtil.getLoginIdAsLong()` 写入 exchange attribute，再由 `AuthGlobalFilter` 写为下游请求头 `X-User-Id`。
4. `/inner/**` 是**内部接口**，仅供服务间 OpenFeign 调用，**不经过网关、不对外暴露**；演示版未加服务鉴权/白名单，生产需限制内网访问或加签名。
5. 本文接口的鉴权分类：
   - **公开**：网关公开路径，无需 token；
   - **需要登录**：网关校验 token 后注入 `X-User-Id`，业务侧 `UserContext.requireUserId()`；
   - **内部接口**：不经网关，由服务间调用。
6. **运营权限**：本微服务切片内**没有**要求运营权限的接口。`GET /users/me` 仅在 `UserVO.isAdmin` 中给出运营标记（`role_flags & ershou.admin.role-flag`，默认 8），由前端决定是否展示运营入口。

## 三、网关路由表

来源：[`GatewayRoutesConfig.java`](../ershou-cloud/ershou-cloud-gateway/src/main/java/com/ershou/cloud/gateway/config/GatewayRoutesConfig.java)。

Spring Cloud Gateway 按**声明顺序**匹配（每个 route 的 order 递增），因此**特例必须写在通配之前**。本表顺序即源码声明顺序：

| 顺序 | 路由 ID | 匹配条件 | 目标 | 说明 |
| --- | --- | --- | --- | --- |
| 1 | `ershou-user-auth` | `/api/v1/auth/**` | `lb://ershou-user-service` | 认证接口 |
| 2 | `ershou-user-schools` | `/api/v1/schools/**` | `lb://ershou-user-service` | 学校/校区 |
| 3 | `ershou-user-me` | `/api/v1/users/me` | `lb://ershou-user-service` | 当前用户 |
| 4 | `ershou-user-legacy` | `/api/v1/users/**` | 旧单体 `8080` | 公开主页及未迁移用户接口 |
| 5 | `ershou-item-categories` | `/api/v1/categories`、`/api/v1/categories/**` | `lb://ershou-item-service` | 分类表在 `ershou_item` 库 |
| 6 | `ershou-item-mine` | `GET /api/v1/items/mine` | 旧单体 `8080` | 特例：我的发布仍在单体，避免被下一条 `GET /items/**` 劫持 |
| 7 | `ershou-item-get` | `GET /api/v1/items/**` | `lb://ershou-item-service` | 商品读；受 Sentinel 限流 |
| 8 | `ershou-item-write` | `/api/v1/items/**`（非 GET） | 旧单体 `8080` | 商品写路径未迁移 |
| 9 | `ershou-order-meetup` | `/api/v1/meetup-orders/**` | `lb://ershou-order-service` | **整段**转 order-service（存在已知缺口，见第十节） |
| 10 | `ershou-legacy-ws` | `/ws/**` | `ws://127.0.0.1:8080` | WebSocket 暂留单体 |
| 11 | `ershou-legacy-api` | `/api/v1/**` | 旧单体 `8080` | 兜底反代（admin/platform/map/files/search/cart/favorites…） |

**匹配原则说明**

- 第 3 条 `/users/me` 必须早于第 4 条 `/users/**`，否则会被反代到单体。
- 第 5 条分类路由早于后面的 `/api/v1/**` 兜底；第 6 条 `GET /items/mine` 必须早于第 7 条 `GET /items/**`，否则 `mine` 会被当作 `Long` 路径参数解析而 400。
- `legacyUri` 默认 `http://127.0.0.1:8080`、`wsUri` 默认 `ws://127.0.0.1:8080`，均可用 Nacos `ershou.gateway.legacy-uri` / `ershou.gateway.ws-uri` 覆盖。
- 网关转发 HTTP 超时：`connect-timeout=3000ms`、`response-timeout=10s`（Nacos `ershou-gateway.yaml`）。

**网关限流**

`SentinelGatewayConfig` 对路由 `ershou-item-get`（即 `GET /api/v1/items/**`）设置 QPS 限流，阈值取 `ershou.gateway.item-qps`（默认 5，间隔 1 秒）。超限由 `SentinelGatewayBlockHandler` 返回：

- HTTP 状态 **429**
- 响应体：`{"code":429,"message":"请求过于频繁，请稍后重试","data":null}`

## 四、公开路径规则

来源：[`PublicPaths.isPublic(method, path)`](../ershou-cloud/ershou-cloud-gateway/src/main/java/com/ershou/cloud/gateway/config/PublicPaths.java)。判断顺序如下：

| 顺序 | 规则 | 说明 |
| --- | --- | --- |
| 1 | `OPTIONS *` | 一律放行（CORS 预检不可能带 token） |
| 2 | `/api/v1/auth/` 前缀 | 登录/注册/发码/登出，任意方法 |
| 3 | 非 GET 请求 | 除上面 auth 外，后续公开规则**只对 GET 生效** |
| 4 | `/api/v1/schools` 前缀 | 学校/校区公开读 |
| 5 | `/api/v1/categories` 或 `/api/v1/categories/` | 分类公开读 |
| 6 | `/api/v1/map`、`/api/v1/trade-points` 前缀 | 地图/点位公开读（反代单体） |
| 7 | `/api/v1/platform/shop/` 前缀 | 平台店铺公开读（反代单体） |
| 8 | `/api/v1/search/status` 前缀 | 搜索状态公开读 |
| 9 | 正则 `^/api/v1/users/\d+/profile$` | 用户公开主页（反代单体） |
| 10 | `/actuator/health`、`/actuator/info` 前缀 | 健康检查 |
| 11 | `/ws` 或 `/ws/` 前缀 | WebSocket 握手；聊天模块自行校验 `?token=` |
| 12 | `/api/v1/items` 或 `/api/v1/items/**` | 商品读公开；**排除** `/api/v1/items/mine`（我的发布需登录） |
| 13 | 其他 | 需要登录 |

> `/inner/**` 不经过网关，因此不在公开路径之列；即使请求网关也不会有对应路由（仅兜底 `/api/v1/**`，`/inner/**` 不匹配任何路由）。

## 五、user-service 接口（6 个）

### 1. 发送短信验证码
- **方法与路径**：`POST /api/v1/auth/sms-code`
- **归属服务**：user-service
- **鉴权**：公开
- **请求参数**：

| 位置 | 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| Body | phone | String | 是 | 手机号，正则 `^1[3-9]\d{9}$` |

- **请求体**：
  ```json
  { "phone": "13800000000" }
  ```
- **响应示例**：
  ```json
  {"code":0,"message":"ok","data":null,"traceId":"a1b2c3d4e5f60708"}
  ```
- **业务规则 / 校验**：
  - 验证码写入 Redis **db1**，key `ershou:user:sms:code:{phone}`，TTL **5 分钟**。
  - 同一手机号每天发码上限 `ershou.sms.max-per-day`（默认 10）：Redis `ershou:user:sms:limit:{phone}:yyyyMMdd` 自增，首次设置 1 天过期。
  - `ershou.sms.mock=true`（默认）时不真发短信，固定验证码 `ershou.sms.mock-code`（默认 `123456`），仅打日志。
  - 字段校验失败由 `GlobalExceptionHandler` 返回 10001 + 具体字段提示。
- **可能错误码**：`10001` 手机号格式错误；`10004` 当日发码次数已达上限；`90001` Redis 等系统异常。

### 2. 手机号验证码登录
- **方法与路径**：`POST /api/v1/auth/login`
- **归属服务**：user-service
- **鉴权**：公开
- **请求参数**：

| 位置 | 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| Body | phone | String | 是 | 手机号，正则校验 |
| Body | code | String | 是 | 验证码 |
| Body | schoolId | Long | 否 | 默认 1；新用户建号时使用 |
| Body | campusId | Long | 否 | 默认 1；新用户建号时使用 |
| Body | deviceId | String | 否 | 设备号，登录时更新到用户记录 |

- **请求体**：
  ```json
  {
    "phone": "13800000000",
    "code": "123456",
    "schoolId": 1,
    "campusId": 1,
    "deviceId": "device-abc"
  }
  ```
- **响应示例**：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": {
      "token": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
      "user": {
        "id": 1001,
        "nickname": "同学0000",
        "avatar": null,
        "phone": "138****0000",
        "schoolId": 1,
        "schoolName": "示例大学",
        "campusId": 1,
        "campusName": "主校区",
        "creditScore": 100,
        "creditLevel": 1,
        "shopName": null,
        "shopIntro": null,
        "identityFlag": 0,
        "publishLimit": 5,
        "chatLimit": 20,
        "newUser": true,
        "roleFlags": 1,
        "isAdmin": false,
        "createdAt": "2026-10-30T12:00:00"
      }
    },
    "traceId": "a1b2c3d4e5f60708"
  }
  ```
- **业务规则 / 校验**：
  - 校验验证码：mock 且输入等于 `ershou.sms.mock-code` 直接通过；否则比对 Redis 中的验证码。校验通过后删除验证码 key。
  - 按 `phone_hash` 查 `sys_user`：不存在则**轻注册**——手机号 AES 加密存 `phone`、`phone_hash` 存哈希；昵称 `"同学" + 手机号第 8 位起的后 4 位`；`schoolId/campusId` 缺省 1；`roleFlags=1`、`identityFlag=0`、`creditScore=100`、`creditLevel=1`、`riskScore=0`、`deviceAccountCount=1`、`publishLimit=5`、`chatLimit=20`、`status=1`。
  - 已存在用户：`status=3` 视为封禁直接拒绝；否则更新 `last_login_at` 与 `device_id`。
  - `StpUtil.login(userId)`，token 写 Redis **db0**（与旧单体 8080、网关 8088 共享会话，token 互通）。
  - 响应 `user` 的字段与单体 `UserVO` 逐项对齐；手机号解密失败时不下发 `phone`。
- **可能错误码**：`10001` 参数校验失败；`20001` 验证码错误或已过期；`20002` 账号已被限制；`90001` 系统异常。

### 3. 退出登录
- **方法与路径**：`POST /api/v1/auth/logout`
- **归属服务**：user-service
- **鉴权**：公开（网关 `/api/v1/auth/**` 放行）；逻辑上需要携带有效 token 才有会话可删
- **请求参数**：无
- **请求体**：无
- **响应示例**：
  ```json
  {"code":0,"message":"ok","data":null,"traceId":"a1b2c3d4e5f60708"}
  ```
- **业务规则 / 校验**：
  - 调用 `StpUtil.logout()` 删除当前 token 的会话；会话在 db0，旧单体侧同步失效。
  - 异常被捕获并 debug 记日志，**按幂等处理**，始终返回成功。
- **可能错误码**：正常无业务错误；极端系统异常 `90001`。

### 4. 当前登录用户
- **方法与路径**：`GET /api/v1/users/me`
- **归属服务**：user-service
- **鉴权**：需要登录
- **请求参数**：

| 位置 | 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| Header | Authorization | String | 否（经网关时必须） | `Bearer <token>`，由网关鉴权 |
| Header | X-User-Id | Long | 否 | 网关内部注入；直连服务调试时不用 |
| — | 无业务参数 | — | — | — |

- **请求体**：无
- **响应示例**：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": {
      "id": 1001,
      "nickname": "同学0000",
      "avatar": null,
      "phone": "138****0000",
      "schoolId": 1,
      "schoolName": "示例大学",
      "campusId": 1,
      "campusName": "主校区",
      "creditScore": 100,
      "creditLevel": 1,
      "shopName": null,
      "shopIntro": null,
      "identityFlag": 0,
      "publishLimit": 5,
      "chatLimit": 20,
      "newUser": false,
      "roleFlags": 1,
      "isAdmin": false,
      "createdAt": "2026-10-30T12:00:00"
    },
    "traceId": "a1b2c3d4e5f60708"
  }
  ```
- **业务规则 / 校验**：
  - 身份来源：优先 `UserContext`（网关 `X-User-Id`，由 `UserContextInterceptor` 写入）；直连服务且无该头时回退 `StpUtil` 解析 `Authorization`（共享 db0，所以单体 token 也认）；两者都没有 → 10002。
  - 按 id 查 `sys_user`，不存在 → 10002。
  - 学校/校区名称分别查本服务 `school`、`campus` 表回填；`isAdmin = (roleFlags & ershou.admin.role-flag) != 0`。

### 11. 内部：锁定库存
- **方法与路径**：`PUT /inner/items/{id}/lock?qty=1`
- **归属服务**：item-service
- **鉴权**：内部接口（仅供 Feign；不经网关、不对外）
- **请求参数**：

| 位置 | 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| Path | id | Long | 是 | 商品 id |
| Query | qty | Integer | 否 | 锁定数量，默认 1；null 或 ≤0 在 Service 内按 1 处理 |

- **请求体**：无
- **响应示例（成功）**：
  ```json
  {"code":0,"message":"ok","data":1,"traceId":"a1b2c3d4e5f60708"}
  ```
- **响应示例（失败）**：
  ```json
  {"code":0,"message":"ok","data":0,"traceId":"a1b2c3d4e5f60708"}
  ```
- **业务规则 / 校验**：
  - 单条条件 UPDATE：`UPDATE item SET status = CASE WHEN stock - qty = 0 THEN 4 ELSE 2 END, stock = stock - qty WHERE id = ? AND status = 2 AND stock >= qty`。
  - 影响行数 1 = 锁定成功（库存扣减；若扣到 0 同时置 `status=4` 已售出）；0 = 商品不存在/不在售/库存不足。
  - **不抛业务异常**：失败也返回 `code=0, data=0`，由调用方按“锁定失败”处理。
  - 方法带 `@Transactional`，作为 Seata AT 分支参与全局事务；回滚由 `undo_log` 自动还原，不写补偿逻辑。
  - 成功后删除 Redis db2 详情缓存 `ershou:item:detail:{id}`；缓存删除失败只告警。
- **可能错误码**：业务上只有 `data=1/0`；系统异常 `90001`；服务不可达时由调用方 fallback 返回 90001。

- **请求体**：

  ```json
  }
  ```

- **响应示例**：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": {
      "id": 3001,
      "orderId": 3001,
      "orderNo": "202610301200001234",
      "itemId": 2001,
      "itemTitle": "九成新自行车",
      "itemCover": "https://example.com/cover.jpg",
      "buyerId": 1002,
      "sellerId": 1001,
      "quantity": 1,
      "dealPrice": 120.00,
      "status": 2,
      "statusText": "待面交",
      "pointId": null,
      "remark": "周六下午方便",
  ```

- **业务规则 / 校验**：
  - 当前用户来自网关 `X-User-Id`，业务侧 `UserContext.requireUserId()`。
  - 数量校验：`quantity` 先归一化为 ≥1；超过 `ershou.order.max-qty`（Nacos 默认 99，`@RefreshScope` 热更新）→ 10001「单次最多购买 N 件」。
  - Feign `GET /inner/items/{id}` 查商品：
    - Feign 返回非 0：`30001` 转 30001；其余（含 fallback 90001）转 90001；
    - 商品 `status != 2` → 30006「商品当前不可购买」；
    - `stock < quantity` → 10001「库存不足（剩余 N 件）」；
    - `sellerId == buyerId` → 10001「不能购买自己发布的商品」。
  - Feign `PUT /inner/items/{id}/lock?qty=` 扣库存：`data != 1` → 30004「商品刚被其他同学抢走，看看同款？」；非 0 code → 90001。
  - 插入 `meetup_order`：`orderNo = yyyyMMddHHmmss + 4 位随机`；`buyerId/sellerId/itemId/itemTitle/itemCover/quantity/dealPrice` 均来自请求与商品快照；`status = ershou.order.default-status`（默认 2=待面交）；`sellerConfirmAt=now`、`rescheduleCount=0`。
  - 事务：`@GlobalTransactional(name="create-meetup-order")` + `@Transactional`。流程为「Feign 查商品 → Feign 锁库存（AT 分支）→ 插单（AT 分支）→ debugFail 抛异常 → 全局回滚」。
  - `debugFail=true`：扣库存与插单之后抛 `BizException(SYSTEM_ERROR, "演示用失败：debugFail=true 触发 Seata 全局回滚")`，响应 `code=90001`，商品库存由 undo_log 还原、订单不落库。
  - 正常提交后发布 `OrderCreatedEvent`，`OrderEventPublisher` 在 `AFTER_COMMIT` 发送 MQ `ershou.order.topic` / `order.created`，消息体为 JSON 字符串 `{orderId,orderNo,itemId,buyerId,quantity,createdAt}`；MQ 发送失败只记日志，不影响已提交订单。
  - 返回前按 id 回查一次订单，带出 DB 默认生成的 `createdAt` 等字段。
  - 面交单状态文案：1 待卖家确认 / 2 待面交 / 3 已完成 / 4 已取消 / 5 已失效 / 6 爽约 / 7 纠纷中。
- **可能错误码**：`10001` 参数/数量/库存/自购；`10002` 未登录；`30001` 商品不存在；`30004` 锁定失败；`30006` 商品状态不可购买；`90001` 商品服务不可用或 debugFail 回滚。

## 八、Feign 契约与降级

来源：[`ItemClient.java`](../ershou-cloud/ershou-order-service/src/main/java/com/ershou/cloud/order/feign/ItemClient.java)、[`ItemClientFallback.java`](../ershou-cloud/ershou-order-service/src/main/java/com/ershou/cloud/order/feign/ItemClientFallback.java)。

### 8.1 客户端定义

```java
@FeignClient(name = "ershou-item-service", contextId = "itemClient", path = "/inner/items",
        fallback = ItemClientFallback.class)
public interface ItemClient {
    @GetMapping("/{id}")
    Result<InnerItemVO> get(@PathVariable("id") Long id);

    @PutMapping("/{id}/lock")
    Result<Integer> lock(@PathVariable("id") Long id, @RequestParam("qty") Integer qty);
}
```

| 方法 | HTTP | 路径 | 入参 | 返回 |
| --- | --- | --- | --- | --- |
| `get` | GET | `/inner/items/{id}` | `id` | `Result<InnerItemVO>`，不存在 code=30001 |
| `lock` | PUT | `/inner/items/{id}/lock?qty=` | `id`、`qty` | `Result<Integer>`，1 成功 / 0 失败 |

### 8.2 超时与降级

| 项 | 值 / 行为 | 来源 |
| --- | --- | --- |
| 服务名 | `ershou-item-service`（Nacos 服务发现，`lb://`） | `@FeignClient(name)` |
| contextId | `itemClient` | `@FeignClient(contextId)` |
| 连接超时 | 3000ms | Nacos `feign.client.config.default.connect-timeout` |
| 读取超时 | 5000ms | Nacos `feign.client.config.default.read-timeout` |
| Sentinel 降级开关 | `feign.sentinel.enabled=true` | Nacos `ershou-order-service.yaml` |
| fallback | `ItemClientFallback`（`@Component`） | `@FeignClient(fallback)` |
| 降级返回 | `Result.fail(90001, "商品服务暂不可用")` | `ItemClientFallback` |
| 网关到 order 的超时 | 10s | `ershou-gateway.yaml` `response-timeout` |

- item-service 不可用（宕机 / 熔断 / 超时）时走 fallback，返回 `code=90001`，不会把 500 直接抛给前端。
- `MeetupOrderService.loadItem` / `lockStock` 把 Feign 异常、fallback 90001、非 0 code 统一转成 `BizException(SYSTEM_ERROR, "商品服务暂不可用")`；`GET` 返回 30001 时转 `ITEM_NOT_FOUND`；`lock` 返回 `data=0` 时转 `ITEM_LOCKED(30004)`。
- `mine` 的 Feign 补全是**尽力而为**：异常/非 0 时使用订单快照，不影响列表。

```text
  ▼
AuthGlobalFilter（GlobalFilter，order=-100）
  ├─ 先删除客户端自带的 X-User-Id（防伪造）
  └─ 写入真实 X-User-Id
  ▼
下游服务 UserContextInterceptor（common 自动装配，拦截 /**）
  ├─ preHandle：ApiHeaderSupport.resolveUserId(request) → UserContext.setUserId
  ├─ afterCompletion：UserContext.clear()
  ▼
业务代码 UserContext.getUserId() / UserContext.requireUserId()
   └─ requireUserId() 在无用户时抛 BizException(NOT_LOGIN=10002)
```

要点：

- **网关不把 token 解到业务层**，只透传数值型 `X-User-Id`；下游服务（item/order）不解析 token。
- `X-User-Id` 缺失/非法时 `ApiHeaderSupport.parseUserId` 返回 null，`UserContext.getUserId()` 为 null；需要登录的接口必须调用 `requireUserId()`，否则会以匿名身份执行。
- `GET /users/me` 额外支持**直连服务**（无 `X-User-Id`）时回退 `StpUtil`，因为 user-service 与网关共享 db0 会话。
- `X-Trace-Id`：网关 `TraceIdGlobalFilter`（WebFilter，最高优先级）有则复用、无则生成 16 位，写入请求头与响应头；下游 `TraceIdFilter` 沿用并放入 MDC，写入 `Result.traceId`。
- 公开接口也可能带登录态：`SaReactorFilter` 只要 `StpUtil.isLogin()` 为 true 就会注入 `X-User-Id`，因此公开读接口在登录后能拿到用户上下文（但当前商品读接口未使用该上下文）。

## 十一、已知缺口与注意事项

1. **order-service 能力不全**：只实现了 `POST /api/v1/meetup-orders`（创建）和 `GET /api/v1/meetup-orders/mine`（我的列表），但网关把整个 `/api/v1/meetup-orders/**` 转给 order-service。因此下列路径经网关会直接 **404**（order-service 无对应 Handler）：
   - `GET /api/v1/meetup-orders/{id}`（详情）
   - `GET /api/v1/meetup-orders/todo-count`
   - `POST /api/v1/meetup-orders/{id}/accept`、`/reject`、`/cancel`、`/confirm`
   - `PATCH /api/v1/meetup-orders/{id}/point`
   - 以及其他未来新增的 `/meetup-orders/**` 子路径
   
   实现时可二选一：补齐 order-service 这些接口；或把特例路由（详情/动作类）显式反代回旧单体 8080，并放在第 9 条通配之前。
2. **`/inner/**` 无鉴权**：内部接口直接暴露在服务端口（8082/8083），演示版没有服务间签名或网段限制；生产必须加白名单/鉴权。
3. **商品写路径与“我的发布”仍在单体**：`GET /api/v1/items/mine` 与所有非 GET `/api/v1/items/**` 经网关反代 8080；item-service 只读 + 扣库存 + 销量累加，不承担发布/审核/上下架。
4. **用户其他接口仍在单体**：除 `/users/me` 外的 `/api/v1/users/**` 均反代 8080；运营后台等也在单体。
5. **分类归属已修正**：`ItemQueryController` 的类注释仍写着“分类路由到 user-service”，实际 `GatewayRoutesConfig` 已把 `/api/v1/categories` 指到 item-service，以网关源码为准。
6. **`GET /api/v1/items` 限流**：默认 QPS 5（`ershou.gateway.item-qps`），压测/演示时容易触发 429，可通过 Nacos 调大。
7. **运营权限**：本切片没有需要运营权限的接口；`UserVO.isAdmin` 只是标记位，不是鉴权依据。要实现运营接口，需要在网关或服务侧补充角色/权限校验。
8. **`traceId` 顶层位置**：`Result.traceId` 是响应顶层字段，不要写进 `data`（本文个别示例为避免重复仅作排版说明，实际以 2.1 节结构为准）。
