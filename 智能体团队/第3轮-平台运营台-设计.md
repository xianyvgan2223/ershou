# 第 3 轮 · 平台代卖运营台（独立操作台）设计与开发契约

> 版本：v1（2026-10-17）｜ 作者：`lead`
> 背景：上一轮把「平台代卖」能力做进了原运营后台（`AdminShell` 内嵌子页），受 `max-width:1440px` + 200px 侧栏 + 商店页布局限制，**表格被截断、信息密度低、观感小气**。本轮给平台管理者一个**全新独立、通栏大气的运营台**，并补齐后台管理接口。
> 本轮是**真开发轮**：先读本文件，按第六节文件所有权互不重叠地并行开发。

---

## 一、目标与范围

### 交付
1. **独立全屏 Shell**：新路由 `/console/platform`，不套商店 `DefaultLayout`、不套 `AdminShell`；左侧 248px 深色侧栏 + 顶部 64px 工具栏 + 通栏内容区（无 1440 限制，padding 28px，最大 1760px 居中兜底）。
2. **7 个页面**：概览 Dashboard / 平台商品 / 代卖点 / 优惠券 / 秒杀场次 / 平台订单 / 缓存运维。
3. **后端管理接口补齐**（设计 3.x）：概览统计、平台商品列表/编辑/上下架、优惠券 CRUD、秒杀场次与商品 CRUD、平台订单分页、Redis 缓存统计。
4. **入口迁移**：`AdminShell` 侧栏移除「平台代卖点」、头部加醒目「平台运营台 →」按钮；旧路由 `/admin/platform-points` 重定向到 `/console/platform/points`；`/platform` 商城页对管理员显示「运营台」入口。
5. 文档收口（Lead）：功能清单 / README / 开发日志。

### 非目标（写进文档，别顺手做）
- 平台订单**强制取消/退款**（需要动订单状态机与库存回收，下轮）
- 平台管理员独立账号体系（仍复用 `role_flags & 8` 的运营身份）
- 移动端运营台

## 三、后端接口契约（`platform-dev` 实现）

统一前缀 `/api/v1/platform/admin`，**每个接口第一行 `adminAuthService.requireAdminId()`**；返回 `Result<T>` / `PageResult<T>`；写操作后做缓存失效/ES 同步/Redis 预热（见 3.8）。默认校区 `campusId=2` 缺省。

### 3.1 概览统计 `GET /overview?campusId=2`
```json
{"platformItemOnSale":4,"platformItemTotal":4,"pointCount":3,
 "couponCount":3,"couponTotalStock":250,"couponClaimed":0,
 "flashSceneId":1,"flashSceneTitle":"官方严选 · 限时秒杀","flashSceneStatus":2,
 "flashStockLeft":10,"flashStockTotal":10,"flashSold":0,
 "orderToday":0,"orderTotal":0,"gmvToday":0.00,"gmvTotal":0.00,
 "pendingPickup":0,"waitingConfirm":0,"lowStockItems":2,"expiringFlashHours":72}
```
- `orderToday`/`gmvToday`：`meetup_order` 中 `seller_id=平台账号` 且 `created_at >= 今天 0 点`；`gmv` 用 `deal_price*quantity`；`pendingPickup`=status 2，`waitingConfirm`=status 1。
- `lowStockItems`：在售平台商品 `stock<=2` 的数量；`expiringFlashHours`：进行中场次距 end 的小时数（无场次给 null）。

### 3.2 平台商品管理
| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/items?pageNum=1&pageSize=10&status=&keyword=&campusId=2&pointId=` | `PageResult<AdminPlatformItemVO>`，**含全部状态**（1 审核中/2 在售/4 已售出/5 已下架/7 已过期）；`keyword` 匹配 title |
| PUT | `/items/{id}` | body `{title?,price?,stock?,platformPointId?}`；校验属于平台商品；改标题/价/库存/点位；清 item 缓存 + ES 同步 |
| POST | `/items/{id}/offline` | 置 `status=5`；清缓存 + ES |
| POST | `/items/{id}/online` | 置 `status=2`、`expire_at=NOW()+30 天`；清缓存 + ES |

`AdminPlatformItemVO`：`{id,title,price,originalPrice,coverUrl,stock,status,statusText,pointId,pointName,sellerType,viewCount,publishedAt,expireAt}`

### 3.3 优惠券管理
| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/coupons?campusId=2` | `List<AdminCouponVO>`；含 `claimedCount`、`leftStock`（Redis 读，未预热回退 total-claimed）、`statusText` |
| POST | `/coupons` | body `CouponSaveDTO`（name/type/thresholdAmount/discountAmount/discountRate/totalStock/perUserLimit/startAt/endAt/campusId/status） |
| PUT | `/coupons/{id}` | 同上；**已发放数 > 新 totalStock 时拒绝**（400） |
| POST | `/coupons/{id}/status?status=0|1` | 启停；保存后触发券缓存失效 + 库存重建 |

`AdminCouponVO`：`{id,name,type,thresholdAmount,discountAmount,discountRate,totalStock,perUserLimit,startAt,endAt,status,statusText,campusId,claimedCount,leftStock}`

### 3.4 秒杀场次管理
| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/flash-sales?campusId=2` | `List<AdminFlashSaleVO>`（场次 + 商品明细 + 实时剩余） |
| POST | `/flash-sales` | body `FlashSaleSaveDTO`（title/startAt/endAt/status/campusId/sort） |
| PUT | `/flash-sales/{id}` | 同上（可改时间/状态） |
| POST | `/flash-sales/{id}/items` | body `FlashSaleItemSaveDTO`（itemId/seckillPrice/seckillStock/perUserLimit/sort）；校验 item 是平台商品 |
| DELETE | `/flash-sales/{id}/items/{itemId}` | 移除场次商品 |
| POST | `/flash-sales/{id}/status?status=1|2|3` | 预告/进行中/结束；切状态后重建 Redis 秒杀缓存 |

`AdminFlashSaleVO`：`{id,title,status,statusText,startAt,endAt,sort,campusId,items:[{itemId,title,coverUrl,originPrice,seckillPrice,seckillStock,perUserLimit,soldCount,leftStock,sort}]}`

### 3.5 平台订单 `GET /orders?pageNum&pageSize&status&keyword`
- 只查 `meetup_order.seller_id = 平台账号(1000)`；`keyword` 匹配 order_no/item_title；按 id 倒序。
- `PageResult<AdminPlatformOrderVO>`：`{id,orderNo,itemId,itemTitle,itemCover,buyerId,buyerNickname,quantity,dealPrice,status,statusText,pointId,pointName,createdAt,verifiedAt}`
- 联 `sys_user` 取买家昵称、联 `platform_consign_point` 取点名（`point_id` 是平台点 id）。

### 3.6 缓存运维
| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/cache/stats` | `{warmupLockHeld:boolean,totalKeys:int,keys:[{key,type,ttl,value}]}`：扫描 `ershou:platform:*`，String 给值（库存）/Hash 给 size、TTL 秒；**只读** |
| POST | `/cache/refresh` | 已有实现，保留 |

### 3.7 代码组织（platform-dev）
- 新增：`controller/PlatformConsoleController.java`（或不新增，扩展 `PlatformAdminController` —— **建议新增独立 controller**，路径 `/api/v1/platform/admin`，避免单文件过大）；
- 新增 service：`PlatformConsoleService.java`（统计 + 订单 + 缓存统计），券/场次管理扩展 `PlatformCouponService`/`PlatformFlashSaleService`；
- 新增 VO：`AdminPlatformItemVO`、`AdminCouponVO`、`AdminFlashSaleVO`、`AdminPlatformOrderVO`、`PlatformAdminOverviewVO`、`PlatformCacheStatsVO`；新增 DTO：`FlashSaleItemSaveDTO`、`AdminItemUpdateDTO`（如无）；
- 复用：`AdminAuthService.requireAdminId()`、`ItemIndexService.syncById`、`CacheEvictor`、`PlatformCacheService`；
- **不改数据库结构**（本轮管理能力基于现有表）；需要写入券/场次时可复用 `CouponSaveDTO`/`FlashSaleSaveDTO` 并补校验。

### 3.8 写操作的一致性要求
- 商品改/上下架 → `ItemIndexService.syncById` + `CacheEvictor.itemChanged`；
- 券增改/启停 → 失效券列表缓存 + 重建该券 Redis 库存（重新按 DB 计算 `total-stock-claimed`）；
- 场次增改/加删商品/切状态 → 重建该场次秒杀 Redis 库存与 users hash（复用 warmup 的单场次逻辑，**不要整库重建**）。
